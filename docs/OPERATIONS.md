## 0.5) الإيقاف اللطيف وإعادة النشر (مهم على Wispbyte)

لوحات الاستضافة تُرسل **SIGTERM** عند كل إعادة تشغيل أو نشر أو تعديل متغيّرات،
ثم تقتل العملية بـ **SIGKILL** بعد ~١٠ ثوانٍ.

البوت يعالج الإشارة صراحةً:

| ما يحدث | الأثر |
|---|---|
| تُستلم `SIGTERM` / `SIGINT` / `SIGQUIT` | يُوقف استقبال تحديثات جديد فورًا |
| مهامّ خلفية جارية (نسخ احتياطي، نبضة، تحليل) | تُنتظر حتى **٥ ثوانٍ** لتُكمل |
| مهمة لم تنتهِ في المهلة | تُلغى، وتُنفّذ كتل `finally` (إغلاق ملفات/معاملات) قبل الخروج |
| الخروج | نظيف برمز **٠**، وليس ١٤٣ (مقتول) |

**لماذا يهمّك عمليًا:** قبل هذا كان كل نشر يقتل البوت في منتصف العمل، والنتيجة:

- ملف يُرفع لقناة التخزين **ناقصًا** (ويظهر للمستخدم «فشل الرفع» مع أن الملف موجود جزئيًا).
- معاملة SQLite **مفتوحة** ⇒ `database is locked` أو WAL غير مكتمل عند التشغيل التالي.
- نسخة احتياطية نصف مكتوبة.

**ما عليك فعله:** لا شيء — يعمل تلقائيًا بـ`python main.py` على أي منصّة.
الشيء الوحيد المفيد: أعطِ اللوحة مهلة إيقاف **١٠ ثوانٍ على الأقل** إن كان
الإعداد متاحًا (Wispbyte يوفّرها في إعدادات الخدمة).

### فحص مسار البيانات عند الإقلاع

قبل أي عمل، يتحقّق البوت أن مجلد `data/` **قابل للكتابة** فعليًا (يكتب ملفًا
ويحذفه). إن كان نظام الملفات للقراءة فقط يظهر فورًا:

```
✖️ مجلد data غير قابل للكتابة (PermissionError: ...)
   على Wispbyte/Docker: اجعل مجلد العمل قابلًا للكتابة،
   أو اضبط DATABASE_URL على مسار داخل وحدة تخزين دائمة.
```

بدل الخطأ الغامض لاحقًا: `sqlite3.OperationalError: unable to open database file`.

### الأحداث المطلوبة من تيليجرام

`allowed_updates` تُشتقّ تلقائيًا من شجرة الراوترات (`resolve_used_update_types`)
وتُطبع في السجل عند الإقلاع، بدل قائمة مكتوبة بيد. عمليًا: أي معالج جديد على
حدث آخر (`edited_message`، `my_chat_member` …) يعمل مباشرة بلا خطأ صامت.

## 0.6) سرعة الإقلاع: البوت يخدم فورًا، والتنزيل في الخلفية

### ما كان يحدث (سبب «البوت بيبطأ الاستضافة»)

`python main.py` كان ينفّذ التجهيز **حاجبًا قبل** فتح اتصال تيليجرام:

```
pip install  →  التحقّق الكامل من الحزم  →  أخيرًا: البوت
```

على لوحة تمسح القرص عند كل إعادة نشر تعني إعادة كل ذلك **من الصفر** في كل
تشغيل. النتيجة: عشرات الثواني إلى دقائق من قرص وشبكة ومعالج مشغولة، والخدمة
لا تخدم تحديثًا واحدًا. اللوحة تراها بطيئة/معلّقة فتُعيد تشغيلها — فتبدأ من
الصفر مرة أخرى (حلقة).

### ما يحدث الآن

| المرحلة | التوقيت |
|---|---|
| فتح المنفذ الصحي (`PORT`) | فورًا — قبل أي شيء |
| تنظيف مخابئ بايثون | أجزاء من الثانية |
| فحص الحزم الأساسية | ~١٫٨ ثانية |
| **البوت يبدأ استقبال التحديثات** | **~٢ ثانية** |
| التحقق الكامل من الحاجيات | **في الخلفية**، ولا يعطّل شيئًا |

مخرجاته تُكتب في `data/install.log` بدل ملوّثة سجل البوت.

### العلامة الدائمة: لا إعادة تنزيل كل إقلاع

كانت علامة «جُرِّب التنزيل وفشل» تُكتب داخل `.ocr/` في المشروع — وعلى لوحة
تمسح القرص تضيع، فتُعاد المحاولة في **كل** إقلاع. الآن تُكتب في كل مسار
ممكن: `.ocr/.attempted` و`$TMPDIR/zakr-ocr.attempted` و`$HOME/.zakr-ocr.attempted`.


### تفعيل الوضع الحاجب القديم (إن أردت)

```bash
ZAKR_SELF_INSTALL=1    # تحقّق كامل إجباري قبل الإقلاع
```
أو اتركه: الافتراضي الآن هو الأسرع والآمن.

### المنفذ الصحي يقول الحقيقة

| الحالة | الرمز | المعنى |
|---|---|---|
| يجهّز | `503` | `{"status":"starting","ready":false}` |
| يخدم التحديثات | `200` | `{"status":"ok","ready":true}` |

قبل ذلك كان يرجّع `200` **دائمًا** حتى لو كان البوت يجهّز — فتصنّفه اللوحة
«حيًّا» وهو لا يخدم أحدًا، ولا تعطيه مهلة الإقلاع التي يحتاجها.

## 1) التشغيل الإنتاجي

### systemd (موصى به على VPS)

`/etc/systemd/system/library-bot.service`:

```ini
[Unit]
Description=Telegram Library Bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=botuser
WorkingDirectory=/opt/library-bot
ExecStart=/opt/library-bot/.venv/bin/python /opt/library-bot/main.py
Restart=always
RestartSec=5
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now library-bot
journalctl -u library-bot -f
```

### نقطة الدخول الموحّدة `main.py` (الأمر الواحد على أي منصّة)

```bash
python main.py
```

هذا هو الأمر الذي يُكتب في خانة التشغيل في **كل** المنصّات. ما يفعله:

| الخطوة | ماذا | يحتاج root؟ |
|---|---|---|
| ① | يكتشف حزم بايثون الناقصة ويُثبّتها بالاستيراد الفعلي | لا |
| ② | يجهّز `.env` (سيرفر) أو يقرأ متغيّرات اللوحة (استضافة) | لا |
| ④ | يمسح `__pycache__` و`.deb` المؤقتة | لا |
| ⑤ | يفتح منفذًا صحيًّا إن وُجد `PORT` (بعض المنصّات تُسقط الخدمة بدونه) | لا |
| ⑥ | يشغّل البوت | لا |

**متى يُشغَّل التجهيز؟** فقط لو نقصت حزمة (أو `ZAKR_SELF_INSTALL=1`).
في التشغيل العادي لا يضيع ثانية واحدة — يمرّ مباشرة إلى البوت.

#### الفرق بين الملفات الأربعة

| الملف | لمن |
|---|---|
| `main.py` | **الجميع** — اللوحات والسيرفرات والجوال. لا يفترض bash ولا صلاحيات |
| `self_install.py` | يُستدعى تلقائيًا من `main.py` — أو يدويًا للتشخيص (`--check`) |
| `setup.py` | من يريد خطوات مفصّلة ببايثون (يفوّض إلى `setup.sh` لو موجود) |
| `setup.sh` | من يريد خطوات مفصّلة بـbash، مع `--docker` و`--systemd` و`--test` |

> ⚠️ `setup.py` **لم يعد يفشل** لو غاب bash: يُكمل المسار الكامل ببايثون.
> كان يفشل قبل ذلك، وحاويات Alpine وبعض صور اللوحات بلا bash إطلاقًا.

### سكربت التشغيل `setup.sh` (التثبيت بأمر واحد)

```bash
./setup.sh              # تثبيت كامل + فحص ذاتي
./setup.sh --start      # تثبيت + تشغيل
./setup.sh --docker     # دوكر
./setup.sh --systemd    # خدمة ٢٤ ساعة
./setup.sh --test       # الاختبارات
./setup.sh --check      # فحص بلا تثبيت
```

سمات التصميم: `set -Eeuo pipefail` (يفشل مبكرًا وبوضوح) · **لا يستبدل
`.env` موجود** · لا يعيد إنشاء `.venv` · يتحقّق من شكل التوكن/الآيدي قبل
الحفظ (ويُترك القيمة كما هي مع تحذير بدل تخمين) · يقرأ القيم من
`ZAKR_BOT_TOKEN`/`ZAKR_OWNER_ID`/`ZAKR_STORAGE_CHANNEL` أو من الأنبوب
للتشغيل الآلي · **فحص ذاتي بلا شبكة** (يبني المخطط في قاعدة مؤقتة ويستورد
كل المعالجات) · صلاحية `.env` تصبح `600`.

### Docker (بديل)

```dockerfile
FROM python:3.13-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "main.py"]
```

```bash
docker build -t library-bot .
docker run -d --name library-bot --env-file .env \
```

### Railway (بديل سحابي بلا إدارة سيرفر)

الملفات جاهزة في جذر المشروع: `Dockerfile` (بلا حزم نظام)
و`railway.toml` (بناء Docker + أمر التشغيل + إعادة تشغيل عند الفشل).

1. ارفع المشروع إلى GitHub (الخاص ممكن).
2. من [railway.app](https://railway.app): **New Project ← Deploy from
   GitHub repo** واختر المستودع — هيكتشف الـ Dockerfile لوحده.
3. من إعدادات الخدمة اختر منطقة أوروبا (Amsterdam) إن أُتيحت لباقتك.
4. من تبويب **Variables** أضف:

   | المتغير | القيمة |
   |---|---|
   | `BOT_TOKEN` | توكن البوت من @BotFather |
   | `OWNER_ID` | رقمك العددي (من @userinfobot) |
   | `STORAGE_CHANNEL` | آيدي قناة التخزين `-100...` (البوت أدمن فيها) |
   | `DATABASE_URL` | `postgresql+asyncpg://...` من Supabase (وضع **Session pooler**، منفذ 5432) |

   من غير `DATABASE_URL` هيقع على SQLite المحلي، ونظام ملفات Railway
   مؤقت فتضيع البيانات مع كل نشر. الجداول تُبنى تلقائيًا عند الإقلاع.
5. انشر وراقب **Deploy Logs** حتى سطر `البوت @... يعمل`.
6. ⚠️ **نسخة واحدة فقط** (Replicas = 1): نسختان تتزاحمان على تحديثات
   تيليجرام. ولا حاجة لأي Port — البوت long-polling بلا HTTP.

أعطال معروفة: `asyncpg` غائب ⇒ ينهار اتصال Supabase (مُصلح في
`requirements.txt`)؛ استخدام منفذ 6543 (Transaction pooler) يكسر
العبارات المُجهّزة — التزم بـ 5432.

> 📌 **الدليل المبسّط للتشغيل** (بلا تفاصيل تقنية، بالعربي، مع أربع طرق
> تشغيل) هو قسم «التشغيل في 10 دقايق» في [`README.md`](../README.md).
> هذا القسم هنا للتفاصيل والحالات الاستثنائية.

### الإعداد من `.env.example`

```bash
cp .env.example .env     # الملف موجود في الأرشيف ومشروح سطرًا سطرًا
```

الأسطر الإلزامية ثلاثة فقط: `BOT_TOKEN` · `OWNER_ID` · `STORAGE_CHANNEL`.
والبوت يعمل كاملًا بدون أي مفتاح ذكاء اصطناعي. مفاتيح المزوّدين تُكتب

## 1.5) قراءة الملفات المصوّرة (بلا تثبيت)

### كيف تعمل الآن

الملفات المصوّرة (سكانر/كاميرا) كانت تُقرأ بـ`tesseract` محلّيًا. أُزيل
ذلك المسار بالكامل، وصارت القراءة تمرّ على **وكيل الرؤية الذي يختاره
المستخدم بمفتاحه**.

```
PDF مصوّر  →  PyMuPDF يرسم كل صفحة PNG (داخل بايثون)  →  الوكيل يقرأ  →  نص
```

| الطبقة | الأداة | ملاحظة |
|---|---|---|
| تحويل PDF→صورة | `PyMuPDF` | داخل `requirements.txt` — **بلا poppler ولا أي حزمة نظام** |
| القراءة | وكيل رؤية | OpenAI · Gemini · Anthropic · Azure · xAI · OpenRouter |
| المفتاح | مفتاح **المستخدم** | من ⚙️ إعدادات الذكاء الاصطناعي — لا يُكتب في `.env` |

### لماذا؟

`tesseract` ممتاز: بلا إنترنت، بلا مفتاح، بلا تكلفة. لكنه **حزمة نظام
تحتاج `root`**، وهو ما لا تمنحه لوحات الاستضافة (Wispbyte/Pterodactyl).
كل الحلول السابقة (تنزيل `.deb` واستخراجها محليًا) كانت هشّة ومعقّدة.
المسار الجديد لا يلمس النظام إطلاقًا.

### الثمن — مذكور صراحةً

| الثمن | التفصيل |
|---|---|
| **لا مفتاح = لا قراءة** | بلا مفتاح وكيل يدعم الصور، الملفات المصوّرة **لا تُقرأ**. لا بديل. PDF النصّي يعمل عادي دائمًا. |
| **تكلفة** | كل صفحة تُرسل إلى مزوّد مدفوع (أو حصّة مجانية محدودة). |
| **خصوصية** | صفحات الملف تخرج إلى طرف ثالث. من يحتاج سرّية تامّة يستخدم `AZURE_OPENAI` داخل حسابه. |
| **دقّة** | موديلات الرؤية أقوى في العربي من tesseract عمومًا، لكنها تخطئ في الجداول المعقّدة. |

### حدود التكلفة (في `bot/services/extract.py`)

| الحدّ | القيمة | السبب |
|---|---|---|
| أقصى صفحات لكل ملف | **١٢** | الفاتورة تتضاعف خطيًا مع الصفحات |
| دقّة الرسم | **150 DPI** | كافٍ للقراءة، وأرخص ٤× من 300 |
| أقصى ضلع بعد التصغير | 1600px | لا خسارة قراءة ملحوظة |
| أقصى نص محفوظ | 400 ألف حرف | حماية الفهرسة |

المستخدم يرى رسالة صريحة حين يُقتطع شيء:

```
الملف 40 صفحة — قرأتُ أول 12 فقط (حدّ التكلفة). ارفع الباقي في ملف منفصل.
```

### ماذا يرى المستخدم حين لا يملك مفتاحًا

```
ℹ️ الملف مصوّر — لا أستطيع قراءة نصه.

قراءة الملفات المصوّرة تتم عبر وكيل ذكاء اصطناعي، وليس عندك مفتاح محفوظ.
افتح ⚙️ إعدادات الذكاء الاصطناعي ← أضف مفتاحك، ثم أعد رفع الملف — أو ارفعه
كما هو وسيبقى متاحًا للتنزيل (بلا بحث داخل نصه).
```

**الرفع لا يفشل أبدًا** لأجل ذلك: قراءة النص ميزة مساعدة، لا شرط للرفع.

### مزوّد نصّي (Groq / DeepSeek / Mistral …)

الرسالة تقول السبب والبديل قبل إرسال أي شيء — لا خطأ 400 غامض:

```
‏Groq لا يقرأ الصور — نصّي فقط. اختر مزوّدًا يدعم الرؤية من ⚙️ إعدادات
الذكاء الاصطناعي: OpenAI · Gemini · Anthropic · Azure · xAI.
```

### إعادة قراءة ملفات قديمة

من لوحة الإدارة: ⚙️ → 🔎 إعادة قراءة الملفات بلا نص. تعمل بمفتاح
**من يضغط الزر**، وتُثبّت التقدّم بعد كل ملف (فانقطاع في المنتصف لا
يُعيد من الصفر — ولا يدفع المستخدم الثمن مرتين).

### تنظيف مخلفات المسار القديم

نسخ قديمة من المشروع قد تحمل `~190MB` في `.ocr/` و`models/`:

```bash
python scripts/clean.py --deep     # آمن: لا شيء يقرأها الآن
```

## 1.9) الأداء — ما قِيس فعلًا

الأرقام هنا من قياس على هذا المستودع، لا من تقدير. أعِد القياس بعد أي
تعديل يمسّ هذه المسارات.

| المسار | قبل | بعد | كيف قِيس |
|---|---|---|---|
| استخراج نص PDF (٦٠ صفحة، ساخن) | ١٦١ ms (pypdf) | **٢٠ ms** (PyMuPDF) | نفس الملف، `extract_text` ٥ مرات والوسيط |
| فتح شاشة الإعدادات | ٤ استعلامات | **استعلام واحد** | `get_effective` مع عدّاد `before_cursor_execute` |
| إقلاع الوحدات | ٣.٣ ثانية | لا تغيير | ٨٧٪ منه `aiogram` — خارج كودنا |

### لماذا PyMuPDF للاستخراج؟

① أسرع بفارق واضح (أعلاه)، و② **مُثبَّت أصلًا** لقراءة الملفات المصوّرة،
فلا تبعية جديدة. و③ النص العربي يخرج عربيًا لا «؟؟؟؟؟».

`pypdf` بقي احتياطيًا: لو غاب PyMuPDF أو رفض ملفًا مشوّهًا يُجرَّب تلقائيًا.
سلوك التراجع محميّ بـ`tests/test_pdf_engines.py`.

### حدود لا تُتجاوز

| الحدّ | القيمة | الأثر لو تجاوزته |
|---|---|---|
| نص محفوظ لكل ملف | ٤٠٠ ألف حرف | فهرس ضخم وبحث بطيء |
| صفحات تُقرأ لكل ملف | ١٢٠ | استخراج طويل يحجب الردّ |
| رسالة تيليجرام | ٤٠٩٦ حرفًا | `MESSAGE_TOO_LONG` — والردّ يُقسَّم تلقائيًا |

### تقسيم الردود

`texts.split_for_send` يقسّم عند ٣٨٠٠ حرف (هامش أمان) ويحترم حدود الأسطر
ثم الكلمات. إن قُسّم الردّ **يقول للمستخدم ذلك** — لا قطع صامت:

```
↩️ الردّ طويل (٩٥٠٠ حرفًا) — سيصلك على ٣ رسائل.
```

كانت الترجمة تقتطع عند ٤٠٠٠ حرف بلا إشارة: نص طويل يُترجم كاملًا ثم
يُعرض نصفه. الآن يصل كاملًا.

## 2) النسخ الاحتياطي والاستعادة

### ما الذي يحتاج نسخًا؟

| العنصر | الطريقة |
|---|---|
| قاعدة البيانات | تلقائي كل 12 ساعة + زر `/admin` → 💾 |
| الملفات | موجودة في قناة تيليجرام (خارجة عن البوت) |
| ملف `.env` | انسخه يدويًا — لا يُنسخ تلقائيًا |

## 4.5) البحث الدلالي: TF-IDF والنموذج العصبي

البوت يعمل بطبقتين، والتبديل بينهما لا يغيّر أي نداء في الكود.

### الطبقة الافتراضية: TF-IDF (بلا اعتماديات)

لكل ملف متجه TF-IDF مخزَّن في جدول `file_vectors` (كلمات + أوزان بصيغة JSON).
عند البحث يُحسب تشابه جيب التمام، فتظهر ملفات قريبة في المعنى حتى بلا تطابق كلمات.

يدعم العربية عبر تطبيع صرفي خفيف:

| قبل | بعد |
|---|---|
| أسئلة / اسئلة | اسيل |
| امتحانات | امتحان |
| التغير | تغير |
| المشتقات | مشتق |

**إعادة بناء الفهرس:** `/admin` → ⚙️ الإعدادات → 🔄 إعادة فهرسة البحث

### الطبقة العصبية: تضمين حقيقي متعدد اللغات

```bash
pip install fastembed
```

في `.env`:

```env
EMBEDDING_MODEL=minishlab/potion-multilingual-128M
```

ثم `/admin` → ⚙️ الإعدادات → 🔄 إعادة فهرسة البحث (لحساب المتجهات للملفات القديمة).

| الموديل | الأبعاد | اللغات | الرام المطلوبة |
|---|---|---|---|
| `minishlab/potion-multilingual-128M` | 256 | متعددة (تشمل العربية) | ~2 جيجا حرة |
| `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` | 384 | متعددة | ~2.5 جيجا حرة |
| `minishlab/potion-retrieval-32M` | 512 | إنجليزية فقط | ~600 ميجا |

> ⚠️ **تحقق من الرام قبل التفعيل.** على سيرفر 2 جيجا رام (ومع نظام وبوت يعملان)
> قد يُقتل النموذج 128M بسبب نفاد الذاكرة — والبوت يعود تلقائيًا إلى TF-IDF دون أن يتوقف.
> تحقّق من الحالة: `/admin` → 🩺 تقرير الصحة (سطر «بحث دلالي عصبي»).

**كيف يعمل التبديل:**

```
semantic.rank()  ──►  embed_rank()   لو EMBEDDING_MODEL مفعّل والمتجهات موجودة
                 └─►  tfidf_rank()   غير ذلك (تراجع تلقائي)
```

كل الملفات تُخزَّن بالطريقتين معًا، فالتبديل لا يحتاج إعادة فهرسة إلا عند
تفعيل النموذج لأول مرة.

### الترقية إلى pgvector (PostgreSQL فقط)

عند تجاوز ~5000 ملف يصبح حساب التشابه في بايثون بطيئًا، فيُنقل إلى قاعدة البيانات:

```sql
CREATE EXTENSION IF NOT EXISTS vector;

ALTER TABLE file_vectors ADD COLUMN embedding vector(384);
CREATE INDEX ON file_vectors USING ivfflat (embedding vector_cosine_ops) WITH (lists = 100);
```

ثم استبدل جسم `semantic.embed_rank()` بـ (دون تغيير أي نداء خارجي):

```sql
SELECT file_id, 1 - (embedding <=> :query_embedding) AS score
FROM file_vectors
ORDER BY embedding <=> :query_embedding
LIMIT :limit
```

**لا يتغير أي نداء خارجي** — `hybrid_search()` في `search.py` تستدعي `semantic.rank()`
بنفس التوقيع، فالتبديل محصور في دالة واحدة.

## 7.5) الذكاء الاصطناعي (اختياري)

البوت يعمل بالكامل بلا أي مفتاح. عند إضافة مفتاح تُفعَّل الميزات الذكية.

### الإعداد

مزوّد واحد يكفي — كل الخدمات الكبرى تعرض واجهة متوافقة مع OpenAI:

| `AI_PROVIDER` | الخدمة | من أين المفتاح |
|---|---|---|
| `openai` | OpenAI | platform.openai.com/api-keys |
| `gemini` | Google Gemini (طبقة مجانية سخية) | aistudio.google.com/apikey |
| `groq` | Groq (الأسرع، مجاني بحدود) | console.groq.com/keys |
| `openrouter` | OpenRouter (كل الموديلات بمفتاح) | openrouter.ai/keys |
| `custom` | أي خدمة متوافقة | تحتاج `AI_BASE_URL` + `AI_MODEL` |

```env
AI_PROVIDER=gemini
AI_API_KEY=مفتاحك
AI_MODEL=            # فارغ = الافتراضي المناسب للمزوّد
```

> ⚠️ **أسماء الموديلات تتغيّر بسرعة.** إن ظهر «الموديل غير موجود» فلا تخمّن:
> اعرض القائمة الحيّة من `/admin` → 🤖 الذكاء الاصطناعي → قائمة الموديلات،
> وضع الاسم الصحيح في `AI_MODEL`.

### اختبار الإعداد

`/admin` → 🤖 **الذكاء الاصطناعي** → فحص الاتصال. يرسل طلبًا صغيرًا حقيقيًا
ويكشف خطأ المفتاح أو الموديل قبل أن يراه مستخدم.

### ما لا يفعله الذكاء الاصطناعي (ضمانات)

- **لا ينفّذ أوامر**: مخرجه نص يُهرب قبل إرساله لتيليجرام (`ai.to_html`)،
  فلا وسوم HTML ولا سكربتات.
- **لا يولّد ملفات**، ولا يتصل بأي خدمة غير المزوّد المُعدّ.
- **لا يُسرَّب المفتاح**: يظهر فقط في ترويسة الطلب، وأي رسالة خطأ تُنقّى منه
  قبل العرض أو التسجيل (`_scrub`).
- **لا يستهلك بلا سقف**: حدود صارمة على طول المدخل والمخرج والمهلة وعدد
  المحاولات، وإعادات المحاولة محصورة في 429/5xx/المهلة.
- **محتوى الملفات بيانات لا أوامر**: يُغلَّف بين علامات مع تعليمات صريحة
  لتقليل نجاح «حقن التعليمات» في ملفات PDF المرفوعة.

الموديول: `bot/services/ai.py` — والاختبارات: `tests/test_ai.py`.

## 7.5.5) إعداد الذكاء الاصطناعي — للأدمن فقط، ويكتب في `.env`

**قرار المالك (نهائي):** «تكون الخاصية دى ظاهرة للادمن فقط، ومش ظاهرة
للمستخدمين العاديين»، و«لما أضيف ذكاء اصطناعى، يحصل تغيير في `.env`».

### من يرى الشاشة؟

| الصلاحية | المستوى | ما يظهر له |
|---|---|---|
| طالب | 0 | لا شيء — الزر غير موجود |
| مشرف | 1 | 🛠️ لوحة الإدارة فقط (بلا شاشة الـ AI) |
| أدمن | 2 | 🤖 الذكاء الاصطناعي + 🛠️ اللوحة |
| مالك | 3 | نفس الأدمن (ولا يُنزع) |

**الحجب مزدوج**، وهذا مقصود: إخفاء الزر في القائمة **ليس حماية**، لأن
`callback_data` مجرد نص يرسله أي عميل مخصّص. فكل معالج من معالجات الشاشة
(وعددها 18) يتحقّق من `can_manage_ai()` مرة أخرى، وأي طالب يُرسل
`ai:menu` يدويًا يحصل على «🔒 هذه الإعدادات للأدمن فقط.»

اختبار `test_every_ai_handler_denies_a_student` يرسل **كل** مسار إلى مستخدم
عادي ويتأكد أنه رُفض ولم تُعرض له شاشة — فلو أُضيف معالج جديد بلا حاجز
يسقط الاختبار.

### الكتابة في `.env` — الضمانات

المهم أن الكتابة تحدث فعلًا في الملف، لا في الذاكرة وحدها:

| الضمانة | لماذا |
|---|---|
| **الملف كامل يُقرأ ويُعاد بناؤه** | لا بحث/استبدال أعمى يفسد ملف الأدمن |
| **كل الأسطر الأخرى كما هي** | تعليقاته وترتيبه وقيمه الأخرى لا تُمسّ |
| **السطر المعطَّل يُفعَّل في مكانه** | `# AI_MODEL=x` تصير `AI_MODEL=x` بلا تكرار |
| **كتابة ذرّية** (`os.replace`) | انقطاع الكهرباء لا يترك `.env` نصف مكتوب |
| **نسخة احتياطية `.env.bak`** قبل كل تعديل | الرجوع بخطوة واحدة |
| **صلاحية 600** للملف والنسخة | الملف يحوي مفاتيح — لا يقرأه غير مالك العملية |
| **قائمة بيضاء للمتغيّرات** | `AI_*` فقط — لا يمكن تعديل `BOT_TOKEN` أو `DATABASE_URL` من الشات |
| **المفتاح لا يُسجَّل** | السجل يعرض `sk-s…cdef` مختصرًا فقط |

المتغيّرات المسموح تعديلها: `AI_PROVIDER` · `AI_API_KEY` ·
`AI_MODEL` · `AI_BASE_URL` · `AI_TEMPERATURE` · `AI_TIMEOUT`،
وأي مفتاح بالشكل `AI_API_KEY_<PROVIDER>`.

### التطبيق الفوري بلا إعادة تشغيل

`Settings` مجمّدة (`frozen`)، ومن يفعل `from ..config import settings`
يحمل مرجعًا قديمًا. فبعد كل كتابة:

1. يُحدَّث `os.environ` بقيم الملف — **لازمة**: `load_settings` تستخدم
   `setdefault`، فالبيئة تحتفظ بالقيمة القديمة ولو تغيّر الملف.
2. يُبنى `Settings` جديد ويُستبدل في `config` و`ai` و`settings_service`.
3. فيسري الاختيار على كل المستخدمين في نفس اللحظة.

**التحقّق النهائي** (مُختبر عبر عملية جديدة تمامًا): بعد إعادة تشغيل البوت
يظل `AI_PROVIDER=groq` و`AI_MODEL=llama-3` فعّالين — وهذا هو الفرق بين
كتابة حقيقية في `.env` وكتابة في الذاكرة فقط.

### إذا كان `.env` غير قابل للكتابة

شائع على **Railway/Vercel** (نظام ملفات للقراءة فقط). لا ندّعي النجاح:
يُطبَّق الاختيار في الذاكرة فورًا، وتظهر رسالة صريحة:

> ⚠️ لم أستطع الكتابة في `.env` … طُبِّق الاختيار في الذاكرة فقط وسيضيع
> عند إعادة التشغيل — أضف القيمة يدويًا في لوحة الاستضافة.

### تعارض المفتاح العام (خطأ حقيقي وُجد وأُصلح)

لو كان `AI_API_KEY=AIza…` (Gemini) وبدّل الأدمن إلى Groq بلا مفتاح جديد،
لأُرسل مفتاح Gemini إلى Groq فرجع 401 محيّر. لذلك عند تبديل المزوّد:

- يُحذف `AI_API_KEY` إن كان يخصّ مزوّدًا آخر (يُعرف من بادئة المفتاح).
- ويُعتمد على `AI_API_KEY_<PROVIDER>` إن كان محفوظًا.
- ومفتاح لا تُعرف بادئته (مزوّد `custom`) **لا يُحذف** — لا نخمّن في مال الأدمن.

### شاشة «📄 إعدادات .env الحالية»

تعرض ما يهمّ الذكاء الاصطناعي فقط: المسار، هل الملف قابل للكتابة، وجود
نسخة احتياطية، القيم الفعّالة، و**أسماء** مفاتيح المزوّدين الموجودة —
أما القيم فلا تُعرض أبدًا. ومنها يعدّل الأدمن `AI_MODEL` / `AI_PROVIDER` /
`AI_BASE_URL` مباشرة، أو يحذف متغيّرًا بكتابة «حذف».

### ماذا عن شاشة المستخدم السابقة؟

كانت المرحلة السابقة تُتيح لكل مستخدم حفظ مفتاحه واختياره، مع تبديل
`ai.settings` العالمي حوالين كل تدفّق. أُزيل ذلك الآن، والسبب:

- الإعداد صار واحدًا للجميع في `.env`، فلم يبقَ «اختيار مستخدم» يُطبَّق.
- تبديل كائن عالمي لكل مستخدم كان يجعل اختيار أدمن واحد يظهر لطالب آخر
  في نفس العملية — وهو خطر حقيقي بلا مقابل بعد هذا القرار.

فبقيت `user_ai` مسؤولة عن: تشفير المفاتيح المحفوظة، والقائمة البيضاء،
و`status()`/`active_label()` **للقراءة فقط** بلا أي كتابة على الطبقة العامة.

**ملفات:** `bot/services/env_file.py` (جديد) · `bot/handlers/ai_settings.py` ·
`bot/services/user_ai.py` · `tests/test_env_and_access.py`.

## 7.5.6) السقف اليومي، لوحة الاستهلاك، وسجل التدقيق

ثلاثة أشياء تحمي رصيد المزوّد وتجيب على أسئلة لا يجيبها السجل العادي:
«كم صرفنا؟»، «ليه الميزة بتفشل؟»، «مين غيّر المفتاح؟».

### ١) السقف اليومي

| البند | القيمة |
|---|---|
| السقف الافتراضي للطالب | **30** وحدة/يوم |
| السقف للمشرف فما فوق | ×10 (300) — لأنهم يختبرون الميزة |
| امتحان شامل (30–50 سؤالًا) | يُحسب **5** وحدات (5 نداءات) |
| بقية الطلبات | 1 |

**السقف يُفحص قبل الطلب لا بعده** — الفحص بعد الإنفاق لا يمنع شيئًا.
و«الوحدة» ليست النداء الخام: الامتحان الشامل يستهلك حتى 5 نداءات، فحسبانه
كطلب واحد كان يسمح بحرق السقف كله في امتحان واحد ثم يفقد الطالب الشرح
بقية اليوم. ويُرفض الامتحان الشامل إذا لم يكن المتبقي يكفي (مثلًا 3 وحدات).

الرسالة عند البلاغ **ليست خطأ**: «استخدمت 42 من 30… والمكتبة والبحث
والكويزات وتلخيص PDF المحلي تعمل عادي» — لأن تعطيل كل شيء يبدو عطلًا.

الإعداد قابل للتغيير من لوحة الأدمن (`ai_daily_limit`) دون نشر.

**السياسة المتبعة**: السقف للاستخدام العادل لا للعقاب؛ رفعه أرحم من
منع الميزة نهائيًا عند نفاد طبقة مجانية.

### ٢) لوحة الاستهلاك (`📊 استهلاك الـ AI`)

آخر 24 ساعة أو 7 أيام: عدد الطلبات، نسبة النجاح، المستخدمون النشطون،
التوزيع حسب النوع والمزوّد، أكثر المستخدمين، وأعلى مزوّد فشلًا.

**ماذا يعني «أعلى فشل»؟** إن ظهر مزوّد بنسبة فشل عالية فالمشكلة فيه
(مفتاح/حد/اسم موديل) لا في الطلاب — يُختبر بـ«🧪 اختبر الإعداد».
وزر «🧹 تصفير العدّادات» يحذف السجل بعد ضبط السقف أو بعد اختبار.

**الخصوصية**: يُحفظ **صف بلا محتوى** — من، أي مزوّد، أي نوع، نجح أم لا.
لا نص طلب ولا رد. الأعمدة ستة فقط (يحميها اختبار)، والصفوف تُقلَّم بعد 60 يومًا.

### ٣) سجل التدقيق (`🗂️ سجل التغييرات`)

كل تعديل على `.env` يُقيَّد: من، متى، المتغيّر، القيمة القديمة والجديدة،
والنتيجة (`✅ كُتب` · `⚠️ للقراءة فقط` · `❌ فشل`).

**قاعدة صارمة**: أي `AI_API_KEY*` يُسجَّل كعلامة `«مفتاح»` أو `«حُذف»`
فقط — **لا قيمته أبدًا**، لأن جدول التدقيق يُنسخ ويُقرأ، فلا يجوز أن يكون
طريقًا ثانيًا لتسريب المفتاح. ويُسجَّل تغيير المفتاح فقط عند تغيّر وجوده
(من فارغ إلى مضبوط أو العكس) لا عند كل إعادة كتابة.

**الاستعادة**: زر «↩️ استعادة آخر نسخة» يُرجع `.env` لنسخة سابقة — وهي
شبكة الأمان إن كتب الأدمن قيمة تُبطل الإقلاع ولم يعد يستطيع فتح البوت.
والاستعادة نفسها تُنشئ نسخة قبلها، فتكون قابلة للرجوع.

**النسخ الاحتياطية**: `.env.bak` (آخر تعديل) + `.env.backups/` بخمس نسخ
مؤرخة، كلها بصلاحية `600`.

### ٤) المفتاح المحفوظ كان «ميتًا» (خطأ حقيقي وُجد وأُصلح)

المفتاح الذي يحفظه الأدمن في الشاشة يُخزَّن مشفّرًا في القاعدة، لكن طبقة
الطلب (`ai.key_for`) تقرأ `.env` والبيئة فقط. فكانت الشاشة تقول «عندك
مفتاح» ثم يفشل كل طلب بـ `401` بلا سبب ظاهر — والأسوأ: **لم يكن يُطلب
منه مفتاح جديد** لأنه يبدو محفوظًا.

الإصلاح بثلاث طبقات:

1. `has_usable_key(provider)` تجيب السؤال الصحيح: «هل سيُرسَل مفتاح فعلًا؟»
   (من `.env`)، لا «هل يوجد صف في القاعدة؟».
2. زر **«📥 انقل … إلى .env»** ينقل المفتاح المخزَّن ويختبره — نقل صريح
   لا سحر خفيّ.
3. لافتة في بطاقة المزوّد: «⚠️ مفتاحك المحفوظ غير فعّال».

### ٥) سقف ملف الامتحان

مسار الامتحان من PDF أثقل من الرفع (تنزيل + تحويل صور + استدعاء AI)، فله سقفه
الخاص `EXAM_PDF_MAX_MB` (افتراضي **10** ميجا، أقل من سقف الرفع). الفحص
**قبل التنزيل**، وإلا فملف واحد كبير يجرّ البوت إلى مهلة ويمنع غيره.

### ٦) تحذير التبديل أثناء امتحان جارٍ

لا نمنع — نُعلن: «فيه امتحان جارٍ — التبديل يغيّر أسلوب الأسئلة القادمة
ويجعل المقارنة غير عادلة». لأن تبديل المزوّد في المنتصف يربك الطالب
ويُفسد دلالة تقدّم المستوى.

**ملفات:** `bot/services/ai_usage.py` · `bot/services/audit.py` ·
`bot/services/env_file.py` · `tests/test_ai_limits_and_audit.py`.

## 7.5.7) تسمية المفاتيح `<name>_api_key` وإضافة وكيل من البوت

**طلب المالك:** «لما أضيف مفتاح في البوت يبقى اسمه في `.env` `aiagent_api_key`
— مع تغيير `aiagent` باسم النموذج اللي هضيفه». وقرّر أن التسمية **باسم
المزوّد** لا باسم الموديل (مفتاح واحد يخدم كل موديلات الخدمة)، وأن الإضافة
تكون **من داخل البوت** بلا تعديل كود.

### ١) العقد الجديد للتسمية

| المتغيّر | إلزامي؟ | المعنى |
|---|---|---|
| `<name>_api_key` | للسحابة | المفتاح. لا يُعرض كاملًا في أي شاشة ولا يُسجَّل في اللوج |
| `<name>_base_url` | **نعم** لتفعيل الوكيل | عنوان الـ API (OpenAI-compatible) |
| `<name>_model` | لا | الموديل الافتراضي؛ بلا تحديد يُجرَّب موديل افتراضي |

`<name>`: حروف إنجليزية صغيرة وأرقام و`_`، يبدأ بحرف، ٢–٢٤ حرفًا. يُرفض
`openai`/`gemini`/`groq`… (مزوّدون ثابتون) و`ai`/`bot`/`token`/`admin`…
**السبب:** الاسم يصبح جزءًا من اسم متغيّر بيئة؛ اسم فيه شرطة أو مسافة يفسد
الملف أو لا يُقرأ.

مثال: `aiagent` ⇒ `aiagent_api_key` · `aiagent_base_url` · `aiagent_model`.

### ٢) المسار الكامل داخل البوت

`🤖 الذكاء الاصطناعي` ← `🧩 الوكلاء المضافون` ← `➕ أضف وكيلًا جديدًا`

اسم → عنوان → مفتاح (أو «تخطّي» للمحلي) → موديل (أو «تخطّي»). المفتاح
يُحذف من الشات فورًا، والقيمة تُقنَّع في الردّ. ثم:

1. `env_file.write_value` يكتب المتغيّرات في `.env` (كتابة ذرّية + نسخة احتياطية).
2. `env_file.reload_settings` يقرأ الملف ويستبدل كائن `settings`.
3. `ai.register_agents` يحوّل الوكيل إلى `Provider` حقيقي (`api_style=openai`)
   ويضيفه إلى `PROVIDERS` و`PROVIDER_ORDER` وأشباحه إلى `_registered_agents`.

فيعمل **بلا إعادة تشغيل**: في القوائم والشرح والامتحانات ولوحة الاستهلاك.
والحذف (`ai:agent:del:<name>`) يمسح المتغيّرات الثلاثة، ويُخرج الوكيل من
`PROVIDERS`/`PROVIDER_ORDER`، ويُسجّل العملية في سجل التدقيق.

### ٣) ثلاث علل حقيقية وُجدت في هذه المرحلة

1. **`os.environ` لم يكن يُحدَّث للمتغيّرات الجديدة.** `_settings_from_file`
   كانت تكتب البيئة بشرط `if name in os.environ` — والوكيل الجديد بطبيعته
   ليس في البيئة، فتُكتب قيمته في الملف **ولا تُقرأ أبدًا**. صار الشرط: كل
   اسم صالح يُكتب. (وبذلك صار تغيير `AI_PROVIDER` من الشاشة يسري فعلًا،
   بدل أن تبقى القيمة القديمة في البيئة تغلب الملف.)
2. **`AI_PROVIDER=auto` كان يتجاهل مفاتيح الوكلاء.** كان يرجع `AI_API_KEY`
   العام فقط، فوكيل له مفتاح يظهر «غير مُهيّأ». صار `auto_choice()`:
   المفتاح العام (مع استدلال المزوّد من بادئته) وإلا **أول مزوّد له مفتاح
   خاص** في `.env`.
3. **وكيل بلا `_model` يبقى «غير مُهيّأ».** أُضيف سؤال الموديل في التدفّق،
   و`ai.provider_model(name)` يشرح مصدر الموديل (<name>_model ← AI_MODEL ←
   الافتراضي)، ويُنبَّه الأدمن إن بقي بلا موديل.

### ٤) الأمان

- `is_allowed` يقبل `AI_*` المدرجة + `<name>_{api_key,base_url,model}` +
  `AI_API_KEY_<PROVIDER>` القديم — **ولا يقبل** `BOT_TOKEN`/`DATABASE_URL`.
- `write_value` ترفض أي قيمة فيها سطر جديد أو `\0`: رسالة تيليجرام تقبل
  أسطرًا متعددة، وسطر جديد داخل القيمة يعني كتابة متغيّر آخر في الملف
  (حقن). الفحص في نقطة واحدة تحمي كل المسارات.
- المفتاح يُحذف من الشات قبل أي شيء، ولا يُكتب في اللوج (`_shorten`)،
  ويعود مقنّعًا فقط. والملف بصلاحية `600` مع نسخة `.env.bak`.
- التوافق الرجعي: `AI_API_KEY_<PROVIDER>` لسه يُقرأ (ثانيًا في الأولوية)،
  فالتحديث لا يعطّل إعدادًا قائمًا.

### ٥) الاختبارات

`tests/test_agents.py` (٣٥ اختبارًا): التسمية وعدم الارتداد للصيغة القديمة،
تحقّق الأسماء ومطابقة المحجوزين لمزوّدي `ai` فعليًا، الاكتشاف (مكتمل/ناقص،
وتجاهل المزوّدين الثابتين)، التسجيل و`auto_choice`، وقراءة الملف بعد
الكتابة (`reload`)، وحقن الأسطر الجديدة. الإجمالي: **٧٣٥ ناجحًا**.

## 7.5.8) إدارة المفاتيح: تحديث · تسمية · حذف · إضافة

**الطلب:** «خليني برضه أقدر أحدّث المفاتيح بتاعة الـ API للنماذج لو خلصت،
أو أعدّل عليهم — تسمية أو تحديث أو حذف أو إضافة. وصلح أي علل بعد مسح الكود».

### ١) الشاشة

`🤖 الذكاء الاصطناعي` ← `🔑 إدارة المفاتيح` — تسرد **كل** متغيّر مفتاح في
`.env` (لا المعروف في `PROVIDERS` فقط)، ولكل واحد: `✏️ حدّث` · `🏷️ سمِّ` ·
`🗑️`. وأسفلها: صفوف `➕ مفتاح <مزوّد>` للمزوّدين المعروفين بلا مفتاح،
وشاشة `➕ مزوّد آخر` بالباقي، و`➕ أضف وكيلًا جديدًا` للخدمات غير المعروفة.

### ٢) العمليات — في `env_file` لا في المعالج

| الدالة | الضمان |
|---|---|
| `update_key` | يكتب ثم **يقرأ** ويتحقق؛ يُرجع `KeyResult.ok=False` إن لم تقع القيمة المطلوبة |
| `rename_key` | **كتابة واحدة**: القديم (وكل صيغه) يُحذف والجديد يُكتب — لا نافذة يختفي فيها المفتاح |
| `delete_key` | يحذف المتغيّر **بكل أشكاله** وحدها — لا `_base_url` ولا `_model` |
| `delete_agent` | الثلاثة معًا، ومن يطلبها يصرّح بذلك |
| `key_state` / `list_editable_keys` | الحالة والأسماء فقط، **بلا أي قيمة** |

### ٣) ست علل حقيقية وُجدت بالمسح وأُصلحت

1. **`is_allowed` كانت ترفض `groq_api_key`.** الاسم يخضع لقواعد أسماء
   الوكلاء التي تحجز أسماء المزوّدين — فصار **حفظ مفتاح لمزوّد ثابت
   مستحيلًا**. الاستثناء صار صريحًا: أسماء `RESERVED_PROVIDERS` مسموحة
   كأسماء متغيّرات (`groq_api_key`) ومحجوزة كـ«وكلاء جدد».
2. **`AI_API_KEY` العام كان يُكتب بدل اسم المزوّد.** فمفتاح يُحفظ «يعمل»
   ثم يضيع أثره عند تبديل المزوّد، ويخالف العقد. صار
   `apply_provider` يكتب `<provider>_api_key` ويُنظّف العام إن كان معروف
   المالك (الغامض وحده يُترك — لا نخمّن في مال الأدمن).
3. **المفاتيح المكتوبة بأحرف كبيرة غير مرئية.** `GEMINI_API_KEY` (وهي
   الصيغة التي تنشرها واجهات المزوّدين) لم تكن تُقرأ ولا تُحذف ولا تُعدّل.
   صار `split_agent_var` يطابق اللواحق بلا حساسية لحالة الأحرف،
   و`key_for` يجرّب `NAME_API_KEY` كذلك.
   **وأثناء الإصلاح ظهر خطأ فرعي:** `AI_MODEL` كانت تُقرأ «وكيلًا اسمه
   `ai`» — فحُظر البادئة `ai_` صراحةً واستُثنيت الإعدادات العامة.
4. **كتابة متغيّر كانت تمسح إخوته.** استخدمت `agent_vars_matching` كقائمة
   «تكرارات»، فكتابة `my_agent_base_url` حذفت المفتاح والموديل (خطأ ظهر
   في تشغيل حقيقي). صار `same_var_variants`: **نفس المتغيّر بصيغة أخرى**
   فقط، لا إخوة الوكيل. ويحرسه اختبار انحدار صريح.
5. **التسمية إلى إعداد عام كانت تُقبل.** `rename_key` إلى `AI_MODEL` يفسد
   الإعداد؛ صار الاسم الجديد ملزمًا بلاحقة معروفة.
6. **«الاسم مستخدم بالفعل» كان يمنع نقلًا مشروعًا.** `read_value` تُرجع
   قيمة الصيغة القديمة نفسها، فيُظنّ الاسم الجديد مستخدمًا. صار الحكم على
   **الأسطر الموجودة** (`explicit_variants`) لا على القراءة الاستنتاجية.

### ٤) صيانة عامة (مسح الكود كاملًا)

- **كود ميت أُزيل:** `nav_buttons` · `used_today` · `attempt_stats` ·
  `apply_provider_key` · `_FIELD_MAP` · `EXAM_CHOICES`/`VALID_EXAM_SIZES` ·
  دالة تسمية مكرّرة في المعالج.
- **كاشف حقن التعليمات صار يعمل:** كان دالة معزولة يحرسها اختبار فقط.
  انتقل إلى `tutor` (مكانه الطبيعي) ويُستدعى في `explain` على الموضوع
  والمادة المرفقة، ويُسجَّل كتحذير — الرصد لا المنع، فالمنع الحقيقي أن
  النموذج بلا أدوات ومخرجه مُهرَّب.
- **خطأ صلاحيات:** `admin._owner` كانت تقارن `role == "owner"` بينما بقية
  المشروع يستخدم `level >= 3` — فشاشتان تحكمان على الشخص نفسه بحكمين.
  صار المصدر واحدًا.
- **تهريب HTML:** أسطر تقرير الصحة ونص البث صارت تُهرَّب؛ نص فيه `<` كان
  يجعل الإرسال يفشل (يظهر «فشل: N» بلا سبب).
- **`except: pass` رُوجعت:** الستة المتبقّية تجميلية (تعديل رسالة/حذفها/
  إغلاق عملية) وموثّقة — لا تُخفي عطلًا.

### ٥) الاختبارات

`tests/test_keys_management.py` (٢٥ اختبارًا) + **٥٨٢ ناجحًا** إجمالًا:
سلامة الكتابة (عدم مسح الإخوة)، دمج الصيغ، الأسماء الكبيرة، الإعدادات
العامة، التحديث والتحقق، التسمية (فقدان القيمة/الاسم المستخدم/الاسم
غير الصالح/الصيغة القديمة)، الحذف بكل الأشكال دون الإخوة، العرض بلا كشف
القيم، النسخ الاحتياطية، وإضافة مفتاح لمزوّد بلا سطر.

## 7.6) تحليل المتعلّم والتخصيص

كل مستخدم له ملف تعلّم (`learner_profiles`) يحدّد شكل الشرح والتلخيص
والامتحانات، ويتدرّج مستواه تلقائيًا من نتائجه.

### كيف يُبنى الملف؟

| المصدر | ماذا يعطي | متى |
|---|---|---|
| استبيان بأزرار (4 خطوات) | أسلوب الشرح، الطول، اللغة، أمثلة/تشبيهات/نقاط | أول استخدام، وقابل للتعديل دائمًا |
| نتائج الامتحانات | الدقّة، المستوى، الصعوبة القادمة، نقاط الضعف | تلقائيًا بعد كل امتحان |

**لماذا الاثنان معًا؟** المستخدم يعرف ذوقه (سريع/مفصّل) لكنه لا يعرف
مستواه الحقيقي؛ والنظام يعرف مستواه من النتائج لكنه لا يعرف ذوقه.

### تدريج الصعوبة (المطلوب في التصميم)

```
المستوى 1–3  →  سهل      + نتائج عالية ترفعه إلى متوسط
المستوى 4–6  →  متوسط    + نتائج عالية ترفعه إلى صعب
المستوى 7–10 →  صعب
```

- **الخبرة** = الإجابات الصحيحة × 10 × وزن الصعوبة (سهل 1، متوسط 1.5، صعب 2)
  — فالإجابة الصحيحة في الصعب تساوي ضعفها.
- **100 خبرة = مستوى أعلى**، بحدّ أقصى 10 مستويات.
- **دقّة ≥ 75%** ترفع الصعوبة، و**≤ 45%** تخفّضها.
- **لا يُنزَّل المستوى أبدًا** بسبب امتحان واحد — تُنزَّل الصعوبة فقط.
  الإنزال عقاب يُحبط المتعلّم، وتخفيف الصعوبة يحقّق نفس الهدف تربويًا.
- المستخدم يستطيع تثبيت صعوبة يدويًا (`difficulty_pref`) فتُلغى الأتمتة.

### ضمانات

- **تحقّق من كل قيمة**: `callback_data` مدخل مستخدم قابل للتزوير، فلا
  تُخزَّن أي قيمة قبل مطابقتها بقائمة مغلقة → قيمة مزوّرة تُرفض بـ`ValueError`.
- **`ondelete="CASCADE"`**: حذف مستخدم يحذف ملفه وأحداثه، لا صفوف يتيمة.
- **JSON تالف لا يُسقط البوت**: كل قراءة تمرّ بـ`_load_json` بتراجع آمن.
- **حدود على البيانات**: آخر 10 محاولات لكل صعوبة، وتفاصيل الأحداث 500 حرف.

### أين يظهر ذلك للمستخدم؟

| الشاشة | المحتوى |
|---|---|
| 👤 حسابي | النقاط + أسلوبك + مستواك |
| 🎯 تحليلي | الدقّة، المستوى، الصعوبة القادمة، نقاط الضعف، آخر الامتحانات |
| 🎨 أسلوب الشرح | الاستبيان (4 خطوات) قابل للتعديل في أي وقت |

**ملفات:** `bot/services/learner.py` · `bot/handlers/learner.py` ·
`tests/test_learner.py` · الجداول في `bot/models.py`.

> ملاحظة ترقية: الجدولان الجديدان يُنشآن تلقائيًا عند التشغيل
> (`ensure_schema`). على PostgreSQL مع Alembic نفّذ `alembic upgrade head`
> أو اترك `ensure_schema` ينشئهما.

## 7.7) الشرح والتلخيص الذكي

ميزتان تستخدمان ملف المتعلّم (§7.6) فتخرجان بأسلوب المستخدم ومستواه.

### الشرح (`🧑‍🏫 اشرح لي`)

1. المستخدم يكتب موضوعًا (أو `/explain قانون أوم`).
2. يُبنى طلب من: الموضوع + تعليمات التخصيص + المادة إن وُجدت.
3. الرد يُقسَّم على رسائل إن طال (حدّ تيليجرام 4096).
4. زر **🔄 اشرح بطريقة تانية** يعيد الشرح بالأسلوب الحالي (بعد تغييره مثلًا).

### التلخيص (`📝 تلخيص ذكي`)

- **PDF**: نصّي مباشرة، ومصوّر عبر وكيل الرؤية.
- **نص حر**: يلخّص ما يكتبه المستخدم.
- **تقسيم هرمي** للنصوص الطويلة: كل جزء يُلخَّص ثم تُدمج الملخصات،
  فلا يُبتر النص ولا يُرفض الطلب لتجاوز حدّ المدخل.

### ضمانات (مُختبرة)

| الضمانة | التفصيل |
|---|---|
| **لا اقتطاع صامت** | لو تجاوز النص سقف الأجزاء نُكبّر حجمها بدل بتر المحتوى — كان السقف الثابت يُسقط ربع مستند طويل بلا إشعار |
| **مخرج دائم** | المستخدم لا يُترك بلا نتيجة: ذكي ← محلي ← مقتطف + الأرقام الواردة |
| **لا استثناء للمستخدم** | أي فشل يصل كرسالة عربية مفهومة، لا كخطأ |
| **HTML آمن بتمريرة واحدة** | `html.escape` بدل التهريب المتتابع (الذي كان يُنتج `&amp;lt;`) |
| **محتوى كبيانات** | المادة المرفقة تُغلَّف ولا تستطيع إغلاق حاويتها |
| **حدود** | موضوع ≤300 حرف، وطلب ≤ حدود `ai.py` |

> **الأرقام والمعادلات لا تُسقَط** في أي مسار تلخيص — هي جوهر المادة.

الموديولات: `bot/services/tutor.py` · `bot/handlers/tutor.py` ·
`tests/test_tutor.py`.

## 7.7.5) إدارة مواد المستخدم (تعديل وحذف)

**السياسة:** صاحب الملف يعدّل ويحذف **ما رفعه هو فقط**؛ المشرف والأدمن
يعدّلان أي ملف (لأنهما يراجعان المكتبة أصلًا).

> **لماذا ليست مفتوحة للجميع؟** المكتبة مشتركة بين الطلاب. لو عدّل أي
> طالب أي ملف لصار بإمكانه حذف مادة زميله أو تغيير عنوانها — تدمير
> متبادل بلا رقابة. الملكية تجعل كل مسؤولية على صاحبها.

### التدفّق

```
🗂️ موادي → اختر ملفًا → اختر الحقل → اكتب القيمة → ✅ تم الحفظ
                                └─ أو: 🗑️ حذف → تأكيد
```

### الحقول القابلة للتعديل

| الحقل | الحدّ | ملاحظات |
|---|---|---|
| العنوان | ٢٤٠ حرفًا | مطلوب، لا يكون فاضيًا |
| الوصف | ٢٠٠٠ حرف | **الأسطر تُحفظ** كما كتبتها |
| الوسوم | ٢٠ وسمًا × ٤٠ حرفًا | مفصولة بفاصلة |
| الفئة | — | اختيار من قائمة (لا كتابة حرة) |
| المادة الدراسية | — | اختيار من قائمة |
| رابط خارجي | ٥٠٠ حرف | لازم `http://` أو `https://`؛ اكتب `-` لمسحه |

**`status` ليس حقلًا قابلًا للتعديل** — تغيير حالة الملف (منشور/مرفوض)
قرار إداري لا تحرير شخصي؛ يُدار من لوحة المشرف.

### ما يحدث تقنيًا عند الحفظ

1. **تحقّق** من كل قيمة برسالة عربية واضحة (`EditError`). خطأ التحقّق
   **لا يُخرجك من الشاشة** — تصلّح وتحاول.
2. **إعادة فهرسة** جدول البحث النصي والدلالي. بدونها يظل البحث يُرجع
   العنوان القديم — عطل لا يُلاحَظ إلا بشكوى «بحثت بالاسم الجديد فلم أجد».
3. **تسجيل في `moderation_log`** بعملية `edited` مع أسماء الحقول —
   للشفافية والمراجعة.
4. **حذف ناعم** (`status=deleted`) لا حذف صفّي: النسخة في قناة تيليجرام
   لا تُمسّ، والأثر (من رفع، متى) يبقى.

## 7.7.6) الشرح من مادة (PDF/مكتبة) + حفظ البرومبت حرفيًا

**الطلب:** «لما يضغط زرار الشرح، يحلّل الـPDF حسب الاختيارات اللي قدامه،
ويكتب برومبته، والـAI يجيب نفس اللي كاتبه بالضبط حتى لو فيه رموز.»

### التدفّق

```
🧑‍🏫 اشرح لي → 📄 اشرح من مادة
   ├─ 📄 أرسل PDF  (أو قراءة تلقائية عبر الوكيل لو سكانر)
   ├─ 📚 اختر من مكتبتي   (يستخدم النص المفهرس بلا تنزيل)
   └─ 📝 الصق نصًا
        ↓
   ١/٤ نوع الشرح:    كامل · نقاط · تعريفات · أمثلة · أسئلة · كل قسم
   ٢/٤ التفصيل:       مختصر · متوسّط · مفصّل
   ٣/٤ اللغة:         عربي · إنجليزي · عربي + المصطلح
   ٤/٤ البرومبت الحر ← اختياري  →  🚀 ابدأ الشرح
```

### تحليل المادة — قبل النموذج

التحليل يحدث **محليًا** (بلا شبكة وبلا تكلفة) قبل أي نداء للنموذج:
أقسام · تعريفات · معادلات · أسئلة · أرقام مهمة.

> **لماذا؟** نماذج كثيرة تحدّ المدخل (~١٢٠٠٠ حرف)، وملف من ٣٠ صفحة أضعاف
> ذلك. الاقتطاع الأعمى من منتصف النص يُفقد المعنى — فيخرج الشرح سطحيًا.
> لذلك نبني **خريطة المادة** ونرسلها مع الطلب، ونجزّئ حسب النمط المطلوب.

إذا كان الملف أطول من الحدّ، يُشرَح الجزء الأهم ويُبلَّغ المستخدم صراحةً:

> «ℹ️ الملف طويل — شُرح الجزء الأهم؛ اختر «شرح كل قسم على حدة» لتغطية الباقي.»

### الحفظ الحرفي للرموز — كيف يعمل

هذه أهم نقطة تقنية في الميزة (`bot/services/verbatim.py`):

| المرحلة | ما يحدث |
|---|---|
| ① حماية | رموز برومبتك (`, <, >, ≤, ≥, **, ^, %, code`…) تُستخرج وتُستبدل بعلامات بديلة `U+E000+n` |
| ② الإرسال | النموذج يستلم **العلامات** لا الرموز، ويُطلب منه إعادتها كما هي |
| ③ التهريب | رد النموذج يمرّ بـ`ai.to_html` كاملًا (أمان تيليجرام) |
| ④ الفكّ | العلامات تُستبدل برموزها **مُهشَّمة مرة واحدة** ← فتُعرَض حرفية |

**⚠️ الترتيب حرج:** لو فُكّت الحماية **قبل** التهريب لظهر ترميز مزدوج
(`&amp;lt;`)، ويرى المستخدم `&lt;` بدل `<` — وهو عين ما شكا منه.
ولو أُرسل الرمز **خامًا** في وضع HTML لفشل الإرسال بـ`can't parse entities`.
الاختبار `test_restore_output_displays_symbols_exactly_once_escaped`
يفشل فورًا لو انعكس الترتيب.

### ما تراه بعد الشرح

ترويسة بالنمط/التفصيل/اللغة المختارة، ثم الشرح، ثم سطر:

> 🔒 محفوظة حرفيًا من برومبتك: `= · × · >`

هذا السطر **دليل لا وعد**: يعرض الرموز التي حُفظت فعلًا، فيتأكّد المستخدم
بدل أن يثق بلا إثبات.

### حدود صريحة

- **لا فهم أشكال**: القراءة تستخرج النص فقط. جدول داخل صورة لن
  يُفهم.
- **البرومبت الحر ≤ ١٥٠٠ حرف**؛ المادة المرسلة ≤ ٩٠٠٠ حرف للطلب الواحد.
- **بلا مفتاح AI** تعود رسالة واضحة، لا شرح وهمي.

## 7.8) الامتحانات المولّدة بأزرار

امتحان اختيار من متعدد يُولّده الذكاء الاصطناعي، **بصعوبة تتدرّج مع
مستوى الطالب تلقائيًا**.

### التدفّق

```
📝 امتحان → (سؤال واحد لكل رسالة) → إجابة بزر → السؤال التالي → النتيجة
```

- **سؤال واحد لكل رسالة** لا قائمة طويلة؛ عدّاد «سؤال ٣ من ٥».
- **تخطّي** متاح؛ الإجابة المزدوجة لا تُحتسب مرتين.
- **النتيجة**: صح/إجمالي، النسبة، التقدير، مراجعة الأخطاء، وتقدّم المستوى.

### الأحجام الثلاثة (المطلوبة)

```
📝 امتحان
├── كويز سريع            5 أسئلة    → مراجعة سريعة قبل الحصة
├── امتحان              5–15 سؤالًا → المستخدم يختار العدد بالضبط
├── امتحان شامل        30–50 سؤالًا → مراجعة مادة كاملة
└── من ملف PDF          → 10 أسئلة من محتوى الملف
```

العدد **يُتحقَّق منه على السيرفر** (`exam.is_valid_size`): أي رقم خارج
`5–15` أو `30–50` يُرفض بتنبيه ولا يُنفَق عليه رصيد مزوّد — لأن
`callback_data` قيمة يتحكّم بها المستخدم.

**لماذا لا نداء واحد للشامل؟** طلب 50 سؤالًا في رد واحد يتجاوز سقف
المخرجات عند أغلب المزوّدين فيعود JSON مبتورًا — وهو أكثر أسباب فشل
التوليد. فالشامل يُولَّد على **دفعات 10 أسئلة** (`CHUNK_QUESTIONS`) مع:

- **دمج بلا تكرار**: بصمة أول 80 حرفًا من نص السؤال (`seen`).
- **توقّف عند فشلين متتاليين** (`MAX_CONSECUTIVE_FAILURES`).
- **سقف إجمالي للدفعات** (`MAX_BATCHES = 50/10 + 3 = 8`): مزوّد يعيد
  4 أسئلة كل مرة كان سيجعل الحلقة تدور طويلًا وهي «تنجح».
- **إعلان النقص**: «طلبت 50 سؤالًا، وتولّد 32 صالحًا.» — لا نُخفي الفرق.

مُحقَّق فعليًا: 50 سؤالًا = **5 نداءات**، 50 سؤالًا بلا تكرار؛ ومزوّد
يُعيد 4 أسئلة كل مرة يتوقّف عند 8 نداءات ويُعلن النقص.

### تدرّج الصعوبة (المطلوب في التصميم)

```
المستوى 1–3 → سهل      4–6 → متوسط      7–10 → صعب
دقّة ≥75% ترفع · ≤45% تخفّض · لا إنزال للمستوى أبدًا
```

مُحقَّق فعليًا: 5 امتحانات كاملة ⇒ مستوى 1→4 والمسار سهل→متوسط→صعب.

### التحقق قبل الثقة (مهم)

مخرجات النموذج **نص غير موثوق**، فكل سؤال يمرّ بفحص صارم قبل العرض:

| يُرفض السؤال إذا | السبب |
|---|---|
| `answer` خارج نطاق الخيارات | سؤال بلا إجابة صحيحة |
| خيارات مكرّرة أو فارغة | إجابة ملتبسة |
| نص السؤال فارغ | سؤال بلا معنى |
| JSON تالف | لا شيء قابل للاستخدام |

وإن قلّت الأسئلة الصالحة عن 3 ⇒ **بديل محلي** بدل امتحان ناقص.
محاولة إصلاح JSON **واحدة فقط** (لا حرق رصيد المزوّد).

### الأمان

- `callback_data` للإجابة يُتحقَّق منه مقابل عدد الخيارات الفعلي —
  قيمة مزوّرة تُرفض ولا تُسجَّل.
- إجابة واحدة لكل سؤال (فهرس يُقفل بعد الإجابة).
- نص السؤال والخيارات يُهرب قبل الإرسال (`exam.safe`).
- التصحيح محصّن: إجابات نصية/`None`/خارج النطاق لا تُسقطه (انحدار مُختبر).
- حالة الامتحان تُمسح بعد النتيجة فلا يُستأنف امتحان قديم بمعرّف قديم.

الموديولات: `bot/services/exam.py` · `bot/handlers/exam.py` ·
`tests/test_exam.py`.

## 8) أي منصّة بلا root (Wispbyte · Pterodactyl · Railway · Render · Koyeb)

### القاعدة الأولى

اختر أمر التشغيل: **`python main.py`** — لا شيء آخر. لا `bash setup.sh` ولا
`python setup.py`، لأن كثيرًا من صور الحاويات بلا bash، و`main.py` يفعل نفس
الشيء ببايثون الصافي.

### لماذا لا يعمل `apt-get install` على اللوحات — وكيف حُلّت

| المحاولة | النتيجة |
|---|---|
| `sudo apt-get install tesseract-ocr` | `sudo: not found` أو كلمة مرور مطلوبة (لا طرفية) |
| `apt-get install tesseract-ocr` | `Permission denied` — الكتابة في `/var/lib/dpkg` تحتاج root |
| ❌ النتيجة | البوت يعمل بلا قراءة ملفات مصوّرة |

**الحلّ القديم** كان تنزيل `.deb` بـ`apt-get download` وفكّها بـ`dpkg-deb -x`
داخل `.ocr/` مع ضبط `PATH`/`LD_LIBRARY_PATH`/`TESSDATA_PREFIX`. عمل، لكنه
هشّ: معمارية الصورة، وglibc مقابل musl، وأخطاء `noexec`، وإعادة تنزيل
١٦٠ ميجا على كل قرص يُمسح.

**الحلّ الحالي:** أُزيلت الحاجة كلها. لا حزم نظام، لا `.deb`، لا `root`:

```
PDF مصوّر → PyMuPDF يرسم PNG داخل بايثون → وكيل الرؤية يقرأ → نص
```

### مساحة القرص

| البند | الحجم | ملاحظة |
|---|---|---|
| الكود | ~١.٣ ميجا | بلا مخلّفات |
| حزم بايثون | ~١٧٠ ميجا | في `site-packages` (منها PyMuPDF ~٢٥ ميجا) |
| **الإجمالي** | **~١٩٠ ميجا** | كان ٣٤٠+ مع tesseract وpoppler |

> ⚠️ **لا ترفع سقف `PyMuPDF` إلى `>=2`.** الإصدار 2.x يسحب `onnxruntime`
> و`numpy` و`pymupdf-layout` و`pymupdf4llm` ≈ **٢٤٤ ميجا** مقابل ميزة لا
> نستخدمها. `1.28.x` = **٢٥ ميجا** بلا أي تبعية. حماية هذا الحدّ في
> `tests/test_extract_vision.py::test_pymupdf_is_capped_below_v2`.
| مخلفات نسخة قديمة | `.ocr/` + `models/` ~١٩٠ ميجا | احذفها بـ`python scripts/clean.py --deep` |

### قائمة تحقّق عند فشل التشغيل

1. **`BOT_TOKEN غير مُعدّ`** ← احفظ المتغيّرات ثم **Restart** لا Start.
2. **`حزم أساسية لا تُستورد`** ← مساحة/شبكة. أعد التشغيل — pip يُكمل ما نجح.
3. **`الملف مصوّر — لا أستطيع قراءة نصه`** ← لا مفتاح وكيل عند المستخدم.
   أضفه من ⚙️ إعدادات الذكاء الاصطناعي. الملف نفسه مرفوع ومتاح للتنزيل.
4. **`Address already in use`** ← نسختان من البوت تعملان معًا. نسخة **واحدة**
   فقط (long-polling): نسختان تتنازعان التحديثات.
5. **البوت يعمل ثم يتوقّف** ← غالبًا القاعدة على قرص مؤقت (Wispbyte يمسح
   القرص عند كل نشر). استخدم `DATABASE_URL` خارجيًا (Supabase/Neon).

# دليل النشر متعدد المنصات

## نقطة التشغيل الموحدة

```bash
python -u main.py
```

يجب تشغيل `main.py` من جذر المشروع. على Wispbyte/Pterodactyl يفعّل المشغّل وضع التثبيت الكامل تلقائيًا: يثبت جميع مكتبات الميزات، ثم يجهز OCR، ثم يفحص الاستيراد والأدوات التنفيذية. لا يبدأ البوت إذا فشل أي شرط من هذه الشروط.

## متغيرات البيئة

| المتغير | مطلوب | الاستخدام |
|---|---:|---|
| `BOT_TOKEN` | نعم | توكن Telegram |
| `OWNER_ID` | نعم | Telegram user ID للمالك |
| `STORAGE_CHANNEL` | نعم | قناة/مجموعة تخزين الملفات |
| `DATABASE_URL` | لا | SQLite افتراضيًا؛ PostgreSQL عند الحاجة إلى تخزين دائم خارجي |
| `PORT` | لا | يُستخدم تلقائيًا لفحص الصحة إن فرضته المنصة |

على Wispbyte لا تحتاج إلى ضبط `ZAKR_INSTALL_OCR` أو `ZAKR_INSTALL_OPTIONAL`؛ وضع Wispbyte يفرضهما داخليًا ويثبت المجموعة الكاملة.

## إعدادات المنصات

| المنصة/النوع | أمر التشغيل | ملاحظات |
|---|---|---|
| Wispbyte / Pterodactyl | `python -u main.py` | وضع صارم: كل مكتبات الميزات وOCR إلزامية. يلزم Debian/Ubuntu متوافق ووجود apt-get/dpkg-deb أو أدوات OCR مثبتة مسبقًا. |
| Railway | `python main.py` أو إعداد `railway.toml` | استخدم Volume لـ`/app/data` أو PostgreSQL. اجعل عدد النسخ 1. |
| Render | إعداد Worker دائم | لا تستخدم خدمة قصيرة العمر؛ القرص المحلي قد لا يكون دائمًا. |
| Docker / VPS | `docker build -t zakr-bot .` | صورة Docker مبنية على المجموعة الكاملة وتثبت Tesseract/Poppler. |
| Linux عام | `python main.py` | Python 3.11+، ويفضّل 3.12. |
| Termux | `python main.py` | بعض إضافات ONNX/PostgreSQL لا تتوفر على كل إصدارات أندرويد. |

## مجموعة Wispbyte الكاملة

`requirements-wispbyte.txt` يثبت aiogram وSQLAlchemy وaiosqlite وAlembic وpypdf وhttpx وasyncpg وPillow وNumPy وpytesseract وpdf2image وopenpyxl وONNX Runtime وFastEmbed. كما يجري تنزيل/فحص Tesseract وPoppler وبيانات اللغات العربية والإنجليزية وOSD.

أي فشل في تثبيت مكتبة أو أداة OCR أو فحصها يوقف التشغيل مع رسالة في Console. هذا يمنع الإقلاع الجزئي لكنه يعني أن المنصة يجب أن تسمح باتصالات HTTPS إلى PyPI ومستودعات Debian/GitHub ومساحة قرص كافية. لا يمكن لأي سكربت تجاوز منع الشبكة أو التنفيذ أو نقص مساحة الخطة.

ملفات النماذج الكبيرة لا تُنزّل مع كل إقلاع؛ تُنزّل عند أول استخدام للميزة وتحتاج مساحة دائمة. مفاتيح مزودي الذكاء الاصطناعي الخارجيين تظل مطلوبة لتلك الخدمات.

## التخزين والاستمرارية

- الملفات نفسها تُرفع إلى قناة/مجموعة Telegram المحددة في `STORAGE_CHANNEL`.
- قاعدة البيانات تحفظ الفهرسة والبيانات الوصفية وسجلات المستخدمين.
- SQLite مناسبة عند وجود قرص دائم. المسار الافتراضي `./data/library_bot.db`.
- عند عدم وجود قرص دائم استخدم PostgreSQL عبر `DATABASE_URL`.
- لا تشغّل أكثر من نسخة polling بالتوكن نفسه.
- لا تستخدم منصات serverless قصيرة العمر أو التي توقف العمليات الخلفية؛ المشروع يحتاج عاملًا دائمًا.


## إدخال الإعدادات من Console مباشرة

عند تشغيل `python main.py` أو `python setup.py`، يفحص البرنامج `BOT_TOKEN` و`OWNER_ID` و`STORAGE_CHANNEL` قبل تحميل إعدادات البوت. إذا كانت قيمة ناقصة أو غير صحيحة شكليًا، يطلب إدخالها من الطرفية ويحفظها في `.env` مع الحفاظ على بقية الإعدادات. لا يطبع التوكن.

في لوحات الاستضافة التي لا تعرض stdin كطرفية تفاعلية، فعّل متغير `ZAKR_INTERACTIVE_SETUP=1` إذا كانت Console تسمح بإرسال الإدخال للعملية. إذا كانت المنصة لا تمرر stdin أصلًا، استخدم Variables أو صحّح القيم من لوحة التحكم. القيم الصحيحة في Environment لها الأولوية؛ أما القيمة الفارغة أو غير الصحيحة فيمكن استبدالها بقيمة `.env` صحيحة.

يقبل التشغيل أيضًا الأسماء البديلة `ZAKR_BOT_TOKEN` و`ZAKR_OWNER_ID` و`ZAKR_STORAGE_CHANNEL`. لا تُرسل توكن البوت في المحادثات أو السجلات.

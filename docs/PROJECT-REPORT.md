## ٢) المراحل — ماذا طلبت وماذا سُلِّم

### 🔹 المرحلة ٠ — البناء والفحص الأول

**الطلب:** بناء البوت كاملًا (مكتبة دراسية على تيليجرام).

**سُلِّم:** ٥٢ ملف بايثون — مكتبة متعدّدة المستويات، رفع وتخزين على تيليجرام،
بحث نصي عربي (FTS5 + trigram)، مراجعة مشرفين، كويزات، ترجمة، تلخيص، OCR،
تصدير Excel/JSON، لوحة إدارة، صلاحيات أربع مستويات.

**القرار المعماري:** الملفات **تُخزَّن في قناة تيليجرام** لا على السيرفر —
القاعدة تحمل الفهرسة فقط. النتيجة: السيرفر لا يحتاج مساحة ولا نسخًا احتياطيًا
للملفات، وحدّ الرفع ٢٠ ميجا يُصبح ٢ جيجا عبر `BOT_API_BASE`.

---

### 🔹 المرحلة ٦ — الفحص الشامل

**الطلب:** افحص المشروع كله.

**ما أُصلح:** تنظيف كود ميت · توحيد `setup_common.py` (كانت الدوال منسوخة
حرفيًا في ٣ ملفات) · إغلاق ثغرات في التعامل مع القيم الفارغة ·
**اختبار يكشف جدولًا بلا ترحيل** — كان `learner_profiles` و`learning_events`
موجودين في النماذج بلا ترحيل alembic، فأي مُرقّي يتبع التوثيق ينتهي بقاعدة
ناقصة وينهار «حسابي» و«تحليلي».

---

### 🔹 المرحلة ٧ — إصلاحات أندرويد (١–٤)

**الطلب:** «مش شغال على الموبايل» — أربع مرات متتالية بأعطال مختلفة.

| العِلّة | السبب الحقيقي | الإصلاح |
|---|---|---|
| `unterminated string literal` | المستخدم كتب `python setup.sh` | خطأ شائع — التوثيق يشرحه الآن صريحًا |
| `لم أجد بايثون داخل .venv` | المجلد موجود **فاضيًا** بعد تحديث بايثون | القانون: وجود المجلد ليس دليل سلامته. الآن يُفحص ويُعاد بناؤه |
| فشل `python -m venv` | المشروع في `~/storage` (تخزين أندرويد مشترك: لا روابط ولا تنفيذ) | البيئة في `~/.local/share/zakr-bot/venv` مع واجهة `.venv` |
| `python-bidi` يُسقط كل `pip install` | مشروع Rust بلا عجلة أندرويد، وrustup يرفض ثلاثي أندرويد | نُقل إلى `requirements-dev.txt` فقط، والبوت لا يستورده إطلاقًا |

**درس ثابت:** كل عِلّة صارت اختبارًا في `tests/test_setup_platforms.py`.

---

### 🔹 المرحلة ٨ — الأمان والتشغيل على Wispbyte

**الطلب:** «شغّله على Wispbyte».

**العِلَل المكتشفة والمُصلحة:**
- `apt-get install` يفشل بـ`Permission denied` → الحل: `apt-get download` (بلا root) + `dpkg-deb -x` داخل `.ocr/`
- `setup.py` كان مجرد غلاف يستدعي bash → أُعيد بناؤه نقطة إقلاع مستقلة
- `setup.sh` يسأل أسئلة → **يُعلّق السيرفر للأبد** (لا طرفية). أُضيف وضع `--wispbyte` بلا أسئلة
- `pip install -r` برسالة واحدة مبهمة → تثبيت **واحدة واحدة** مع ذكر اسم الفاشل وسببه

### 🔹 المرحلة ٩ — طبقة الذكاء الاصطناعي

**الطلب:** «عايز البوت يشرح ويولّد امتحانات».

**سُلِّم:** محوّل واحد لـ**٢٢ مزوّدًا** (كلهم متوافقون مع OpenAI API) ·
`ai_guide.py` يشرح مميزات وعيوب كل مزوّد ويوصي حسب الأولوية ·
**سقف استهلاك يومي** + `ai_usage.py` + `audit.py` يسجّل من غيّر `.env`
(بلا أي قيمة سرية) · `env_file.py` يكتب في `.env` ذرّيًا مع نسخ دوّارة وصلاحية `600`.

**قرار الرفض:** لا مخرجات مزيفة عند غياب المفتاح — رسالة عربية واضحة فقط.

### 🔹 المرحلة ١٠ — تحليل المتعلّم والامتحانات

**الطلب:** مستوى يتدرّج + امتحانات بأحجام مختلفة.

**سُلِّم:** `learner.py` (ملف متعلّم ← أحداث ← دقة ← توصيات) ·
`exam.py` بثلاثة أنماط: كويز ٥ · امتحان ٥–١٥ · **شامل ٣٠–٥٠** ·
صعوبة تتدرّج تلقائيًا مع مستوى الطالب.

---

### 🔹 المرحلة ١١ — الشرح الحرفي والمواد

**الطلب (خمس نقاط، بالترتيب):**

1. **المستخدم يعدّل مواده من أي ناحية** (عنوان/وصف/وسوم/فئة/مادة/رابط/ملف) — بواجهة بوت، مستخدم عادي لا مشرف
2. ربط جزء من الشرح بتحليل PDF، مع احترام اختيارات أسلوب التعلّم
3. برومبت المستخدم الحر يوجّه الذكاء الاصطناعي بدقة
4. **الحرفية التامة:** «والـAI لما يشرح البوت يجيب نفس اللي كاتبه بالضبط، حتى لو فيه رموز»
5. `setup.py` و`setup.sh` يشغّلان البوت **كله**

**سُلِّم:** `materials.py` (تعديل/حذف — **صاحب الملف فقط**، والمشرف لأي ملف) ·
`material.py` (تحليل: أقسام · تعريفات · معادلات · أسئلة) ·
**`verbatim.py`** — النص يُحفظ حرفيًا ويُعاد كما هو، والرموز (`<`, `>`, `≤`, `**`,
`x^2`) تُحمى بعلامات خاصة قبل تمريرها للنموذج وتُعاد بعدها.

**قرار نطاق:** الحرفية = **نص برومبت المستخدم** يُعاد حرفيًا في المخرجات — لا
اقتباس حرفي من الـPDF.

**حدود أُعلنت:** لا فهم للصور/الأشكال · برومبت ≤١٥٠٠ حرف · مادة ≤٩٠٠٠ حرف ·
الملف الطويل يُشرح أهم جزء منه ويُقال ذلك.

### 🔹 المرحلة ١٢ — الرفع على GitHub

**الطلب:** «حط ملف البوت على GitHub» ← ثم «مش شغال معايا».

**العِلّة الحقيقية:** الأرشيف لم يكن فيه `.git`، والسكربت كان **يشترطه**:
```
✖ لست داخل مستودع git — فكّ الأرشيف أولًا
```
أي أنه كان لا يعمل عند **أي** من يفكّ الأرشيف.

**الإصلاح:** السكربت يهيّئ المستودع بنفسه (`git init` ← `.gitignore` ← فحص
أسرار ← التزام ← رفع). وأُضيف ضمان الفرع `main` لأن `git init -b` لا يفهمه
ما قبل ٢٫٢٨ فينشئ `master` ويفشل الدفع بلا سبب مفهوم.

**الاختبار:** رفع فعلي إلى خادم git حقيقي — ٨٥ ملفًا وصلت، بلا `.env`، بلا نموذج.

---

### 🔹 المرحلة ١٣ — التشغيل على أي منصّة (الأخيرة)

**الطلب:** «حاول تصلحه بحيث يشتغل على أي منصّة (بما فيهم Wispbyte)، واكتب فيه
الأكواد اللي تخليه ينزل كل متطلبات البوت إجباري، مع مسح كل الملفات الزيادة
وتقليل حجم ملف البوت قدر الإمكان، واعمل مسح كامل للمشروع، وحدث كل ملفات البوت.»

**أربعة أعطال حقيقية اكتُشفت بالاختبار (لا بالتخمين):**

| # | العِلّة | الإثبات | الإصلاح |
|---|---|---|---|
| ١ | `from PIL import Image` في أعلى `ocr.py` كان **يقتل البوت كله** لو غابت Pillow — والسلسلة `main ← upload ← ocr` | `✖ FAILS without OCR libs: ImportError blocked PIL` | استيراد محمي — OCR يتعطّل وحده |
| ٢ | `python setup.py` كان **يموت** لو مفيش bash | حاويات Alpine وبعض صور اللوحات بلا bash | التفويض صار اختياريًا |
| ٣ | نزّل tesseract بنجاح ثم قال «معطّل» (المخابئ قُرئت قبل التنزيل) | محاكاة Wispbyte | `refresh_local_ocr_env()` + **إثبات** بعد التنزيل لا افتراض |
| ٤ | توكن مشوّه = تتبّع بايثون إنجليزي طويل | `TokenValidationError` | فحص الشكل قبل بناء الكائن |

**سُلِّم:** `main.py` (نقطة الدخول الموحّدة) · `self_install.py` (تثبيت ذاتي
بلا root) · `scripts/clean.py` · `Procfile` · `render.yaml` · `nixpacks.toml` ·
`.wispbyte/README.md` · منفذ صحي لـ`PORT`.

**الحجم: ٢٩ ميجا ← ٣٦٨ كيلوبايت** (٨٠ مرة أصغر).

## ٥) الحدود المعلنة — بصراحة

1. **لا فهم للصور أو الأشكال** — الـOCR يقرأ نصًا فقط.
2. **Alpine (musl)** — حزم ديبيان (glibc) لا تعمل؛ البوت يشتغل بلا OCR ويقول ذلك.
3. **Vercel** — ليس منصّة تشغيل بوتات (لا عملية دائمة). هذا طبع long-polling.
4. **حدود الطلب** — برومبت ≤١٥٠٠ حرف، مادة ≤٩٠٠٠ حرف.
5. **ملف واحد فقط لكل نسخة** — نسختان تتنازعان تحديثات تيليجرام.
6. **بدون مفتاح AI** — رسالة عربية واضحة، ولا مخرجات مزيفة أبدًا.

# 📚 ذاكر - مساعدك الدراسى

بوت تيليجرام لإدارة مكتبة مواد دراسية: تصفّح، رفع ملفات، بحث داخل المحتوى، شرح وتلخيص ذكي، امتحانات، ولوحة إدارة.

**الملفات تُخزَّن في جروب/قناة تيليجرام** — قاعدة البيانات تحفظ البيانات الوصفية فقط.

> 👋 **أول مرة تتعامل مع البوت؟** اقرأ [«التشغيل في 10 دقايق»](#-التشغيل-في-10-دقايق) تحت.
> مش محتاج تعرف برمجة — تحتاج 3 حاجات بس: توكن بوت، رقمك في تيليجرام، وقناة فاضية للتخزين.
>
> ⚡ **أمر التشغيل على Wispbyte:** `bash setup.sh --wispbyte` (أو `python setup.py --wispbyte`)
> يثبت مجموعة ميزات الإنتاج كاملة (بما فيها OCR وExcel وONNX وFastEmbed) ويفحصها قبل التشغيل. إذا فشل تثبيت أي اعتماد أو أداة OCR يتوقف بدل تشغيل بوت ناقص. قد يزيد ذلك مساحة القرص ووقت أول إقلاع.
>
> 💡 ولو عايز شرح خطوة بخطوة: `bash setup.sh --start` (أو `python setup.py`).

## نقاط التشغيل المعتمدة

ملفا `setup.sh` و`setup.py` هما واجهتا التشغيل الأساسيتان، وهما المسؤولان عن تجهيز البيئة وتثبيت الاعتماديات وقراءة الإعدادات والتحقق منها وإجراء الفحص الذاتي. بعد نجاح ذلك يستدعي كل منهما `main.py`، وهو بدوره يجهّز نقطة دخول التطبيق ويشغّل `bot.main`. لذلك لا تحذف `main.py` ولا تشغّل `bot.main` مباشرةً على الاستضافة.

- Linux / Wispbyte: `bash setup.sh --wispbyte`
- أي بيئة Python: `python setup.py --wispbyte`
- تشغيل عادي: `bash setup.sh --start` أو `python setup.py --start`
- تجهيز بلا تشغيل: `--no-start`

في اللوحات التي لا تمرّر إدخالًا تفاعليًا، أضف `BOT_TOKEN` و`OWNER_ID` و`STORAGE_CHANNEL` في Startup → Variables. إذا كانت Console تسمح بإدخال stdin، يمكن للـSetup طلب القيم الناقصة مباشرةً.

راجع `docs/SETUP-ENTRYPOINTS.md` ودليل أندرويد للتعليمات التفصيلية.

## 🚀 التشغيل — أمر واحد بس

> **الفكرة:** مش هتعمل أي خطوة بإيدك. في ملف اسمه `setup.sh` جوّه المشروع
> بيعمل **كل** الخطوات لوحده، **واحدة واحدة**، بالترتيب اللي تحت — وبيقولك
> بيعمل إيه في كل خطوة على الشاشة.

```bash
unzip zakr-bot.zip -d zakr-bot && cd zakr-bot
bash setup.sh --start
```

أو شغّل `python setup.py --start`. في الحالتين ملفات Setup تجهّز كل شيء ثم تشغّل `main.py`؛ لا تشغّل `main.py` بدلها عند النشر المعتاد.

> 💡 مفيش `chmod` ولا أي تجهيز قبله — الأمر `bash setup.sh` بيعمل كده لوحده.
> (ولو حبيت: `./setup.sh --start` نفس الحاجة بعد أول مرة.)

> 🚫 **مهم جدًا:** متشغّلوش بـ`python setup.sh` أبدًا.
> السكربت مكتوب بلغة **bash**، فلو شغّلته ببايثون هتلاقي رسالة غامضة:
> `SyntaxError: unterminated string literal`. الرسالة دي معناها بس إنك
> استخدمت الأداة الغلط. الحل: `bash setup.sh --start`.
> (أو `python setup.py --start` — الملف ده موجود مخصوص للموضوع ده.)

| الأمر | يعمل إيه | امتى تستخدمه |

### 🧹 رسالة «لم أجد بايثون داخل .venv» — حلّها بأمر واحد

لو ظهرت لك الرسالة دي (أو `No such file: .venv/bin/python`) فمعناها أن
مجلد `.venv` اتعمل في لحظة كان بايثون فيها ناقص أو اتحدّث بعدها — فيبقى
المجلد موجود وفاضي. **مش محتاج تحذفه بإيدك:**

```bash
bash setup.sh
```

السكربت بقى بيفحص البيئة قبل ما يستخدمها، ولو لقاها مكسورة **بيحذفها
ويبنيها من جديد** لوحده. و`.env` وبياناتك مش بتتأثر إطلاقًا.

> 🛡️ ولو حبيت تعملها يدويًا (نفس النتيجة):
> ```bash
> rm -rf .venv && bash setup.sh
> ```

### ☁️ على أي لوحة استضافة (Wispbyte · Pterodactyl · Railway · Render) — سطر واحد

**السبب الأول اللي بيخلي البوت مايشتغلش على اللوحات:** مفيش `sudo`، ولا `apt`،
وقد لا تمرر بعض اللوحات إدخال Console للعملية؛ عندها لا يمكن ضمان الأسئلة التفاعلية. إذا كانت Console تدعم الإدخال يمكن تفعيل `ZAKR_INTERACTIVE_SETUP=1`. وأي أمر
بيكتب في `/usr` **بيرجع Permission denied**.

**الحل:** أضفت ملف اسمه `self_install.py` يجهّز أي منصّة **بلا صلاحيات مدير**:

| الخطوة | إزاي بتتعمل بلا root |
|---|---|
| حزم بايثون | `pip --user` — مش محتاج صلاحيات أصلًا |
| tesseract + poppler | `apt-get download` (بينزّل `.deb` بس) ← فكّها بـ`dpkg-deb -x` جوه `.ocr/` ← تشغيل بـ`PATH` و`LD_LIBRARY_PATH` موجّهين |
| بيانات العربية | تنزيل `ara.traineddata` مباشرة في مجلد `tessdata` |
| مساحة القرص | مفيش `.venv` ولا حزم نظام — كل حاجة جوه المشروع وقابلة للمسح |

**الطريقة (خطوتين في اللوحة):**

**١) ارفع ملفات المشروع** (Files ← Upload، أو اسحب الـZIP واستخرجه).

**٢) Startup ← Variables** — أضف التلاتة دول:

| المتغيّر | القيمة |
|---|---|
| `BOT_TOKEN` | التوكن من @BotFather |
| `OWNER_ID` | رقمك من @userinfobot |
| `STORAGE_CHANNEL` | آيدي قناتك (يبدأ بـ `-100`) |

**٣) Startup ← Startup Command** — اكتب السطر ده بالظبط:

```
python setup.py
```

اضغط **Start**. خلاص. نفس السطر بيشتغل على Railway وRender وKoyeb وVPS
وعلى جهازك — **بلا أي فرق**.

> 🧠 `python setup.py` يفوّض تلقائيًا إلى `setup.sh` عند توافر Bash؛ والاثنان واجهتان لنفس مسار الإعداد. على Wispbyte يثبت مجموعة الإنتاج الكاملة: مكتبات البوت وOCR وExcel
> وPostgreSQL وONNX وFastEmbed، ثم يفحص الأدوات قبل التشغيل. لو خطوة فشلت يتوقف ويعرض السبب بدل تشغيل نسخة ناقصة.

**إيه اللي هيظهر في سجل اللوحة؟**

```
╔══════════════════════════════════════════╗
║  بوت ذاكر — بدء التشغيل الموحّد          ║
╚══════════════════════════════════════════╝
• تجهيز تلقائي (ناقص: aiogram, sqlalchemy) …
✔ حاجيات بايثون جاهزة (8 حزمة إقلاع متحقَّقة بالاستيراد)
✔ قارئ الملفات المصوّرة جاهز في .ocr/ — ويعمل فعلًا
• نُظّفت 4 مخلّفات (__pycache__/deb مؤقتة)
البوت @your_bot يعمل (المالك: 123456789)
```

> ⚙️ **Wispbyte يستخدم التثبيت الكامل إجباريًا.** لا تضف متغيرات تعطيل OCR أو الإضافات؛ المشغّل يفرض تثبيتها ويتوقف إذا تعذرت.

> ⚠️ **لو الصورة Alpine (musl)** حزم ديبيان (glibc) مش هتشتغل — والسكربت
> بيقولك ده صراحةً بدل خطأ غامض. اطلب صورة Debian/Ubuntu.

> 🔐 **الأمان:** التوكن بيتقرأ من متغيّرات اللوحة بس — **مش بنكتبه في `.env`**
> ولا في `.git/config`.

> ⚠️ **`BOT_TOKEN غير مُعدّ` مع إنك ضفته؟** اضغط **Save** بعد الإضافة وبعدها
> **Restart** (مش Start) — اللوحة مش بتقرأ المتغيّرات الجديدة غير بعد إعادة تشغيل.

### 📱 على أندرويد (Termux) — خطوات مخصوصة

البوت **بيشتغل على الموبايل**، لكن أندرويد مش لينكس عادي: مدير الحزم
`pkg` مش `apt`، وأسماء الحزم مختلفة، وبعض المكتبات مالهاش نسخة أندرويد.
السكربت بيتعامل مع ده كله لوحده — بس لازم تبدأ بالخطوتين دول:

```bash
# ١) في Termux — نصّب الحاجيات الأساسية
pkg update && pkg upgrade -y
pkg install -y python tesseract poppler python-numpy python-pillow curl

# ٢) وصّل الذاكرة (مهم — عشان توصل لمجلد التنزيلات)
termux-setup-storage

# ٣) ادخل مجلد المشروع وشغّل
cd ~/storage/downloads/zakr-bot
bash setup.sh --start
```

| حاجة | على أندرويد |
|---|---|
| **بايثون** | `pkg install python` (السكربت يكتشفه لوحده) |
| **قراءة الملفات المصوّرة** | `pkg install tesseract poppler` + السكربت ينزّل بيانات العربية تلقائيًا |
| **فكّ التواء الصور** (onnxruntime) | ❌ **مش متاح على أندرويد** — بيتخطّى، والـOCR العادي شغّال |
| **دوكر** | ❌ مستحيل داخل أندرويد — استخدم `--start` |
| **systemd** | ❌ مش موجود — استخدم `termux-wake-lock` (تحت) |
| **قاعدة البيانات** | SQLite محليًا (زي أي جهاز) |

> 🔋 **عشان البوت يفضل شغّال بعد قفل الشاشة:**
> 1. `termux-wake-lock` (قبل التشغيل — بيمنع النوم)
> 2. إعدادات أندرويد ← التطبيقات ← Termux ← البطارية ← **غير مقيّد**
> 3. افتح إشعار Termux وسيبه في الخلفية — لو قتلت التطبيق البوت بيقف
>
> ⚠️ ومن الأفضل تحط الموبايل على الشاحن — البوت بيستهلك بطارية مع الوقت.
> وللاستخدام الجدّي ٢٤ ساعة، سيرفر رخيص أو Railway أوفر وأثبت.

> 💡 **رسالة الخطأ الشهيرة:** لو شفت `SyntaxError: unterminated string
> literal` فأنت كتبت `python setup.sh`. الصح: **`bash setup.sh --start`**.

> 📂 **مهم جدًا: مكان المشروع على أندرويد**
> التخزين المشترك (`~/storage/downloads`, `/sdcard`) **لا يدعم الروابط
> الرمزية ولا صلاحية التنفيذ** — والبيئة الافتراضية تحتاجهما، فيفشل
> إنشاؤها هناك دائمًا. السكربت بقى يحلّها تلقائيًا بوضع البيئة في
> `~/.local/share/zakr-bot/venv` وترك واجهة `.venv` في المشروع.
> لكن **الأفضل والأسرع** نقل المشروع لمجلد Termux الخاص:
> ```bash
> cp -r ~/storage/downloads/zakr-bot ~/zakr-bot
> cd ~/zakr-bot && bash setup.sh
> ```

> 🧪 **وإن ظهرت «تعذّر إنشاء البيئة الافتراضية»؟** السبب أن `python -m venv`
> على أندرويد يعتمد على `ensurepip`، وهو يتعطّل عندما يكون pip مثبّتًا في
> حزم النظام (حالة Termux دائمًا). **السكربت بقى لا يستخدم ensurepip
> إطلاقًا**: ينشئ البيئة بلا pip ثم يجهّزه بـ٥ طرق بديلة، ولو تعذّرت كلها
> يكمل ببايثون النظام (نتيجة مكافئة). مفيش حاجة تعملها — أعد `bash setup.sh`.

#### 🅱️ بدوكر (يشتغل في أي مكان بنفس البيئة)

> 📄 اعمل `.env` الأول (الخطوة 3) — `--env-file` بيقرأ منه. وملاحظة: الملف
> **مش** بيتحط جوه الصورة (`.dockerignore` بيستثنيه) حتى لا تتسرّب مفاتيحك
> لو رفعت الصورة لمستودع.

```bash
docker build -t zakr-bot .
docker run -d --name zakr-bot --restart unless-stopped --env-file .env \
  -v "$(pwd)/data:/app/data" -v "$(pwd)/backups:/app/backups" zakr-bot
```

| الأمر | معناه |
|---|---|
| `--restart unless-stopped` | يرجع يشتغل لوحده بعد ريستارت السيرفر أو لو وقع |
| `-v .../data` | قاعدة البيانات تبقى **خارج** الحاوية — متضيعش مع تحديث الصورة |
| `-v .../backups` | النسخ الاحتياطية كذلك |

```bash
docker logs -f zakr-bot     # تتابع الشاشة
docker stop zakr-bot        # توقّفه
docker start zakr-bot       # تشغّله تاني
```

> 🖼️ الصورة بتثبّت OCR والخط العربي جواها — مش محتاج تثبّت الحاجات في الخطوة 2.

#### 🅲 على سيرفر دائم (systemd — البوت شغال ٢٤ ساعة)

على سيرفر أوبنتو رخيص أو كمبيوتر قديم سايبه شغال:

```bash
sudo nano /etc/systemd/system/zakr-bot.service
```

```ini
[Unit]
Description=Zakr Study Bot
After=network-online.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu/zakr-bot
ExecStart=/home/ubuntu/zakr-bot/.venv/bin/python -u -m bot.main
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now zakr-bot
journalctl -u zakr-bot -f        # تتابع الشاشة
```

> 🔁 `Restart=always` يعني البوت يرجع لوحده بعد أي ريستارت أو انقطاع نت.
> غيّر `User` و`WorkingDirectory` لمسارك الفعلي، ولو مش مستخدم بيئة
> افتراضية خلّي `ExecStart=/usr/bin/python3 -u -m bot.main` بدل مسار `.venv`.
>
> 🧾 **مهم**: البوت يقرأ `.env` من **مجلد التشغيل** (`WorkingDirectory`)
> — فتأكد إن `.env` في نفس المجلد ده.

#### 🅳 على Railway (سحابي — من المتصفح)

المشروع فيه `Dockerfile` و`railway.toml` جاهزين، فمش محتاج تعدّل حاجة:

1. ارفع المشروع على **GitHub** (الريبو الخاص مقبول).
2. [railway.app](https://railway.app) ← **New Project** ← **Deploy from GitHub repo** واختار الريبو — هيلقط الـ `Dockerfile` لوحده.
3. تبويب **Variables** ضيف نفس الخمس أسطر بس **بلا ملف**:
   `BOT_TOKEN` · `OWNER_ID` · `STORAGE_CHANNEL` · `AI_PROVIDER` · `groq_api_key`
4. **Deploy** وراقب **Deploy Logs** لحد سطر `البوت @... يعمل`.

> ⚠️ **حاجتان مهمتان على السحابة:**
> 1. **قاعدة بيانات خارجية**: ملفات Railway **مؤقتة** — البيانات تضيع مع كل
>    نشر. ضيف `DATABASE_URL` من [Supabase](https://supabase.com)
>    (`postgresql+asyncpg://...` بمنفذ **5432**، وضع Session pooler).
> 2. **نسخة واحدة فقط** (Replicas = 1): نسختان تتزاحمان على تحديثات
>    تيليجرام. ولا حاجة لأي Port — البوت بيسحب التحديثات (long-polling).

> 💡 **وعلى السحابة كمان**: لأنه ملف `.env` هناك للقراءة فقط، شاشة «تعديل
> `.env`» هتقولك الحقيقة: «طُبِّق في الذاكرة وسيضيع عند إعادة التشغيل» — عدّل
> المفاتيح من تبويب Variables بدلًا منها.

## 🤖 الذكاء الاصطناعي (للأدمن فقط — ويكتب في `.env`)

البوت بيشتغل كامل **من غير أي مفتاح**. لكن لو عايز الميزات الذكية
(الشرح، التلخيص، الامتحانات المولّدة)، الأدمن هو اللي يظبطها — **من البوت

> 👑 **مين يشوف الشاشة؟** الأدمن والمالك بس. الطالب والمشرف **مش شايفين
> الزر أصلًا**، ولو حاولوا يفتحوها بأي طريقة تانية هيقابلهم
> «🔒 هذه الإعدادات للأدمن فقط» — الحجب في الكود مش في الأزرار بس.

| الزر | بيعمل إيه |
|---|---|
| 🎯 **ساعدني أختار** | ٦ أسئلة بسيطة (مجاني؟ عربي؟ خصوصية؟ جودة؟ سرعة؟ سهولة؟) → ترشيح أفضل ٣ |
| 📋 **استعرض كل الخيارات** | ٢٢ مزوّدًا، ٦ في كل صفحة — **مميزات وعيوب وتقييم من ٥ في ٦ حاجات** |
| ⚖️ **قارن بين الأشهر** | مقارنة جانب-بجانب لأشهر ٩ خيارات |
| 📄 **إعدادات .env الحالية** | تشوف الملف وتعدّل `AI_MODEL` / `AI_PROVIDER` / `AI_BASE_URL` من الشات |
| 📊 **استهلاك الـ AI** | كم طلبًا، نسبة النجاح، أكثر مستخدم، وأعلى مزوّد فشلًا |
| 🗂️ **سجل التغييرات** | مين غيّر إيه وامتى — وزر **استعادة آخر نسخة** من `.env` |
| 🧪 **اختبر الإعداد** | بنبعت طلب صغير بجد ونتأكد إن الاختيار شغال فعلًا |
| ⚙️ **موديل محدّد** | تختار الموديل بالاسم، أو تجيب **📡 القائمة الحيّة** من المزوّد |

### ➕ تضيف مزوّد/موديل مش موجود في القائمة؟

أي خدمة بتتكلّم **OpenAI-compatible** (خدمة سحابية أو موديل على جهازك) تقدر
تضيفها من البوت نفسه — من غير ما تفتح كود ولا تعدّل ملف:

**🤖 الذكاء الاصطناعي ← 🧩 الوكلاء المضافون ← ➕ أضف وكيلًا جديدًا**

البوت يسألك ٤ أسئلة: **الاسم** ← **عنوان الـ API** ← **المفتاح** ← **اسم
الموديل**، وكل إجابة بتتكتب في `.env` باسم الوكيل نفسه:

```
aiagent_base_url=https://api.example.com/v1
aiagent_api_key=sk-…
aiagent_model=gpt-4o-mini
```

**القاعدة:** `<اسم الوكيل>_api_key` — لو سمّيته `groq` يبقى `groq_api_key`،
ولو `aiagent` يبقى `aiagent_api_key`. مفتاح واحد بيخدم كل موديلات الخدمة دي.

| الأمر | التفصيل |
|---|---|
| ⚡ **يعمل فورًا** | الوكيل بيتسجّل مزوّدًا كاملًا بلا إعادة تشغيل — يظهر في القوائم والشرح والامتحانات |
| 🔒 **المفتاح** | رسالتك بتتمسح فورًا، والمفتاح بيتخزّن في `.env` بصلاحية `600`، وبيتعرض مقنّع (`sk-a•••••3456`) |
| 🧩 **الإدارة** | شاشة «الوكلاء المضافون» بتوريك كل وكيل وحالة متغيّراته، وبتقدر تحذفه (بيمسح متغيّراته الثلاثة) |
| 🏷️ **الاسم** | حروف إنجليزية صغيرة وأرقام و`_`، ويبدأ بحرف — لأن الاسم بيصبح جزءًا من اسم متغيّر بيئة |
| 🚫 **أسماء محجوزة** | أسماء المزوّدين الثابتين (`openai`, `gemini`, `groq` …) — دول بيتعدّلوا من شاشتهم لا كـ«وكيل جديد» |
| 💻 **موديل محلي** | اكتب **تخطّي** عند المفتاح — Ollama/LM Studio مش محتاجين مفتاح |

> 🔁 **مفاتيحك القديمة مش هتضيع:** الصيغة القديمة `AI_API_KEY_GEMINI` لسه
> مقروءة، فالتحديث مش بيكسر أي إعداد سابق.

### 🔑 تبقى المفاتيح في يدك: تعديلها كلها من شاشة واحدة

المفتاح مش حاجة تتكتب مرة وتتنسى — ممكن يخلص رصيده، أو تدوّر مفتاحًا جديدًا،
أو تغيّر اسمه. الشاشة دي بتديك **٤ عمليات** على أي مفتاح:

**🤖 الذكاء الاصطناعي ← 🔑 إدارة المفاتيح**

| العملية | إزاي | الضمان |
|---|---|---|
| ✏️ **تحديث** | تكتب القيمة الجديدة، ورسالتك بتتمسح فورًا | يُقرأ الملف بعد الكتابة للتأكد أن التغيير وقع فعلًا — مش «تم» كلامية |
| 🏷️ **تسمية** | تكتب الاسم الجديد (`gemini` أو `AI_API_KEY_GEMINI`) | القيمة تنتقل كما هي **بلا فقدان**، والاسم القديم يُنظَّف |
| 🗑️ **حذف** | زر، ثم **تأكيد** | يُمسح السطر (وكل صيغه)، والنسخة `.env.bak` تبقى للرجوع |
| ➕ **إضافة** | لمزوّد معروف بلا مفتاح، أو وكيل جديد بالكامل | يعمل **فورًا** بلا إعادة تشغيل، ويظهر بأنه «مضبوط» |

> 🔄 **بعد تغيير المفتاح** البوت بيختبره ويعرض النتيجة في نفس الرسالة:
> «✅ المفتاح يعمل» أو سبب الفشل — بلا تخمين.

> 🧹 **تنظيف تلقائي:** لو كان عندك نفس المفتاح بصيغتين
> (`GEMINI_API_KEY` و`gemini_api_key`) يُدمجان في سطر واحد عند أول تعديل،
> حتى لا تُقرأ قيمة قديمة بالغلط.

> 🔒 **لا تظهر أي قيمة** في الشاشة — الحالة فقط (`✅ مضبوط` / `⚠️ فارغ`)،
> وكل عملية تُسجَّل في «🗂️ سجل التغييرات» باسم من عملها.

بتغطي: قاعدة البيانات، البحث النصي والدلالي بالعربية، OCR، الكويزات،

> ⏭️ المتخطّى اختبارات تحتاج حزمًا ثقيلة أو نماذج OCR غير موجودة في

مش لازم في البداية — SQLite (الافتراضي) كفاية تمامًا لمكتبة متوسطة. لو احتجت لاحقًا، الكود لا يحتوي أي شيء خاص بـ SQLite عدا جدول البحث (وله تنفيذ بديل جاهز). غيّر سطرًا واحدًا:

```env
DATABASE_URL=postgresql+asyncpg://user:pass@host:5432/dbname

```

## 📦 حجم المشروع — إزاي قلّلته

الحجم اللي بيهمّ مش حجم المجلد على جهازك، بل **اللي بيتبعت للمنصّة**.
اللوحات بتحاسب على المساحة والذاكرة، والرفع البطيء بيفشل في نصّه.

| الحاجة | قبل | بعد | إزاي |
|---|---|---|---|
| نموذج UVDoc | ٣٢ ميجا | **٠** | يُنزَّل عند أول استخدام بتحقّق SHA256 |
| `tests/ocr_corpus` | ٩٥ ميجا | **٠** | للتطوير فقط — منفصل في `zakr-bot-tests.zip` |
| `__pycache__` + مخابئ | ١ ميجا | **٠** | `scripts/clean.py` |
| حزم نظام (.deb) | ٢٧ ميجا | **٠** | تُنزَّل وقت الحاجة ثم تُمسح |
| صورة Docker | +٣٢ ميجا | **أصغر** | أزلت خبز النموذج من `Dockerfile` |

python scripts/clean.py              # نظّف المخلّفات (آمن، لا يمسّ .env ولا الداتابيز)
python scripts/clean.py --dry-run    # شوف بس، بلا حذف
python scripts/clean.py --deep       # + احذف OCR والنموذج (يُعاد تنزيلهم تلقائيًا)
```

> ⚠️ **اللي مش بيتمسّ أبدًا:** `.env` (مفاتيحك) · `data/*.db` (قاعدة بياناتك)
> · `backups/` · `uploads/`. مكتوب ده في `PROTECTED` جوه السكربت نفسه.
